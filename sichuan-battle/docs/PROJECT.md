# 사천성 배틀 기획서

> 최종 업데이트: 2026-07-27 — 교착 선택과 5초 입력 대기 복구

## 보드 생성 규칙

- 12×8 전체 좌표에 face 1~24를 각각 4장씩 시드 기반으로 분산 배치한다.
- 기존의 가로 인접 도미노 48쌍을 미리 만드는 방식은 사용하지 않는다.
- 외곽에 노출된 좌표 쌍을 결정적 PRNG로 선택해, 저장된 48단계 해답이 실제 최대 2회 꺾임·외곽 경로 규칙으로 항상 완주되게 한다.
- 초기 보드와 자동 교착 셔플은 동일한 생성기를 사용하며, 셔플은 남은 face 다중집합·타일 ID·좌표·제거 상태를 보존한다.
- `solution`은 서버 내부 검증용이며 WebSocket snapshot에는 노출하지 않는다.

## 프로젝트 개요

미니게임 천국의 공개 HTTPS 통합 런처에 포함된 1:1 사천성 아이템 대전이다. 친구는 같은 공유기에서도 `https://112.155.2.238`로 접속하며 개별 포트 직접 접속은 운영하지 않는다. 사람 또는 서버가 인증한 AI와 동일한 12×8 초기 배치의 독립 보드에서 3분 동안 짝을 제거하며, 서버가 관리하는 6종 아이템을 연속 사용해 경쟁한다.

## 아키텍처

### 디렉토리 구조

```text
sichuan-battle/
  assets/       # 24종 타일과 배경, 생성 원본·검증표
  lib/          # 규칙, 경로, solver, 아이템, 경기 상태
  public/       # 대기·플레이·결과 UI와 ko/en 클라이언트
  scripts/      # 에셋 재생성·검증
  tests/        # 단위·프로토콜·2브라우저·시각 QA
  bot.js        # 인증된 비브라우저 AI 참가자와 행동 예약 수명주기
  server.js     # 정적 파일과 서버 권위 WebSocket 앱
```

## 알려진 제약사항

- LAN 1:1 전용이며 AI 난이도는 보통 한 종류다. 3인 이상, 온라인 매치메이킹과 모바일 전용 UX는 지원하지 않는다.
- 인증, 인터넷 배포용 부정행위 방지, 영구 전적과 랭킹을 제공하지 않는다.
- 런타임은 생성된 PNG/WebP를 사용한다. 에셋 재생성에는 `scripts/build-assets.mjs`와 원본 파일이 필요하다.
- 390px 화면의 12열 내 타일은 약 28×30px로 일반적인 36px 이상 터치 권장치보다 작다.
- `/favicon.ico`는 별도 리소스가 없어 인앱 브라우저에서 404 메시지가 발생할 수 있으나 게임 동작에는 영향이 없다.

## 입력 및 pending 계약

- 타일 버튼은 `tileId`를 키로 경기 중 같은 DOM 객체를 재사용하며, 상태·locale·ARIA 속성만 제자리에서 갱신한다.
- 실제 `WebSocket.send()`가 성공한 짝 요청만 `requestId`, `matchId`, board revision을 가진 pending으로 전환한다.
- PAIR 응답은 현재 `requestId + matchId`가 모두 일치할 때만 처리하고, revision·경기·연결 변화에서는 pending과 선택을 정리한다.
- 응답이 2초 안에 오지 않으면 입력을 복구하며 늦게 도착한 응답은 상태를 바꾸지 않는다. 이후 권위 `STATE_SYNC`가 실제 보드 결과를 반영한다.
- 교착 선택과 5초 대기는 개인화 snapshot으로 복구한다. 대기 중에는 본인 타일만 잠그고 타이머·상대 행동·효과 만료는 유지하며, 종료 시 합법 수가 있으면 그대로 해제하고 없으면 완주 가능하게 셔플한다.

## 아이템 및 효과 계약

- 아이템 사용은 서버의 `matchId + slotId` 소유권과 `requestId` 중복 캐시로 승인한다. 서로 다른 슬롯은 이전 `inventoryRevision`을 보내도 각각 한 번 처리된다.
- 힌트는 합법 짝이 있을 때만 소비하며 본인 snapshot에 대상 두 타일만 공개한다. 상대 snapshot과 모든 공개 snapshot에는 힌트 경로를 넣지 않는다.
- 잠금·뒤집기·안개 대상은 경기 seed와 사용 순번에서 파생한 결정적 PRNG로 유효 후보 전체에서 비복원 선택한다.
- 방해 타일 플래그는 남은 활성 효과 전체에서 재계산한다. 자동 교착 셔플은 힌트만 정리하고 활성 방해 플래그를 복구한 뒤 완주 가능한 보드를 제공한다.

## 향후 계획

- 실제 두 기기 LAN 환경에서 아이템 빈도와 공격 지속 시간 체감 플레이테스트
- 모바일 터치성을 높일 경우 12열 전체 노출을 유지하면서 타일 간격 또는 선택 보조 방식을 별도 검토
- 필요 시 랭킹·매치메이킹과 AI 난이도 선택을 별도 범위로 검토

## 아이템 및 오디오 계약

- 잠금·뒤집기·안개 대상은 화면 상단(`y < 4`)과 하단(`y >= 4`) quota를 먼저 배분한 뒤 각 절반의 활성 행에 순환 배분한다. 뒤집기 16장은 후보가 충분하면 상·하 8장씩이며, 잉여 수량과 행 내부 타일은 결정적 PRNG로 선택한다.
- 서버·AI·클라이언트는 `lock`, `flip`, `fog`, `hint`, `cleanse`, `shield` 6종 allowlist만 허용한다. 인벤토리는 유효 item/slot ID와 최초 중복 슬롯만 순서대로 남기고, 권위 timed effect는 `lock`, `flip`, `fog`, `hint`만 중앙 정규화해 구버전·unknown·손상 상태를 제거한다.
- 첫 제거는 아이템을 보장하고 이후 기본 드롭률은 14%, 5회 연속 미획득 뒤 다음 기회는 보장한다. 30쌍·48쌍 기대 획득량은 각각 약 7.53개·11.77개로 이전 규칙의 약 1/3이다.
- 아이템 입력 즉시 해당 슬롯을 빈칸으로 낙관 렌더링하고 `requestId + slotId` pending 큐로 정산한다. 응답·권위 snapshot의 도착 순서가 바뀌거나 응답이 유실돼도 1.5초 watchdog이 슬롯을 복구하거나 소비 완료로 정리하며, 100ms 이하 3연타도 각 슬롯을 한 번씩 소비한다.
- 같은 공격 재사용은 기존 `effectId`와 targets를 유지한 채 기본 지속시간으로 `endsAt`만 초기화한다. 정화는 제거할 디버프가 없어도 소비되고 3초 면역을 부여한다.
- 방어막은 `shieldActive` boolean으로 시간 제한 없이 유지되며 다음 유효 공격 한 번만 막는다. 활성 중 내 보드 외곽 glow와 타이머 없는 `1회`/`1 hit` 칩을 표시하고 차단 즉시 제거한다.
- 힌트는 서버가 찾은 실제 연결 가능 쌍의 targets와 path를 본인 snapshot에만 공개한다. 일반 선택 피드백과 독립된 보드 하단 배너, ①·② 배지와 외곽선은 path가 없거나 잘려도 유지하며 해당 쌍 매칭·셔플·경기 종료 때 제거한다.
- 오디오는 첫 pointer 또는 keyboard 제스처 뒤 Web Audio를 시작한다. 낮은 볼륨의 합성 BGM과 선택·힌트·매칭·실패·아이템·공격·방어 차단 SFX를 제공하며 음소거 설정은 `localStorage`에 저장한다.

# 마작 — 프로젝트 작업 지침

서버 권위 4인 일본식 리치마작이다. 사람 1~4명이 방 설정 화면에서 모이고 호스트가 시작하면 빈자리를 서버 관리형 AI가 채운다. 사람이 2명이면 마주 보는 자리(동·서)에 앉는다. UI는 DOM/CSS/SVG이며 외부 이미지 에셋을 쓰지 않는다(`public/assets/key-art.webp`는 런처 카드 전용, GPT Image 원본은 `public/assets/gpt-image-sources/`). 개발 포트 3021.

## 핵심 구조

```text
mahjong/
├── lib/tiles.js    # 패 id(0~135)·종류(0~33), 도라 표시패 변환, 시드 가능한 난수
├── lib/agari.js    # 분해·대기패·향청수·역/부수 평가·점수 계산(순수 함수)
├── lib/game.js     # 대국 상태 머신(MahjongGame) — 모든 규칙 판정과 국 진행
├── lib/ai.js       # AI(easy/normal/hard). viewFor() 뷰만 사용한다
├── lib/hints.js    # 초보 도우미(향청수·대기패·안전패·추천 버림)
├── server.js       # WebSocket 룸, AI 스케줄러, 타이머, 정적 파일
├── public/         # index.html, css/style.css, js/{main,tiles,sounds,fx}.js
└── tests/          # node:test + Playwright UI, record-demo.mjs(두 가상 플레이어 시연 영상 녹화)
```

## 룰 (일본식 리치마작)

- 패 136장(만·통·삭 36×3 + 자패 28), 적도라(5만·5통·5삭 각 1장) 선택. 시작 25,000점, 반환 30,000점.
- 동풍전(동장 4국, 기본)·반장전(동+남 8국). 종료 후 1위가 30,000점 미만이면 서입(동풍전은 남입)하며 최대 4국 연장한다.
- 올라스 친이 1위(30,000점 이상)로 화료/텐파이 유국이면 종료(아가리야메), 0점 미만이면 즉시 종료(도비).
- 역: 리치·더블리치·일발·멘젠쯔모·탕야오·핑후·이페코·역패·해저/하저·영상개화·창깡·삼색동순·일기통관·찬타·치또이츠·또이또이·산안커·삼색동각·산깡쯔·소삼원·혼노두·량페코·준찬타·혼일색·청일색, 도라·적도라·뒷도라. 역만: 국사무쌍·스안커·대삼원·소사희·대사희·자일색·청노두·녹일색·구련보등·스깡쯔·천화·지화(13면 국사·스안커 단기·순정구련·대사희는 더블).
- 13판 이상은 헤아림 역만, 4판 30부·3판 60부는 끊어올림 만관.
- 론은 후리텐(버린 패/동순/리치 후)이면 불가하며 쯔모는 가능하다. 쿠이탕 on/off 옵션.
- 더블 론 허용, 삼가화·사풍연타·사가립직·사깡산료·구종구패는 유국 처리. 유국만관(나가시만관) 지원.
- 식스왑(쿠이카에): 울고 같은 패·반대편 끝 패 버림 금지. 리치 후 암깡은 대기가 바뀌지 않을 때만 허용.
- 미구현: 파오(책임지불), 국사무쌍의 암깡 창깡, 우마·오카 정산(순위·점수만 표시), 관전.

## 게임 불변조건

- 좌석 0~3 고정, 좌석 0이 첫 친이며 친은 `roundNum % 4`다. 자풍은 `(seat - dealer + 4) % 4`.
- 진행 대기 상태는 `game.pending`이 단일 기준이다: `turn`(버림/쯔모/깡) · `reaction`(론/울기 응답) · `ack`(국 결과 확인) · null(종료).
- 모든 변경은 `act(seat, action)`으로만 일어나고 불법 행동은 `{ok:false}`로 거절된다. 서버는 거절 시 `ERROR`와 최신 `STATE`를 보낸다.
- 반응 우선순위는 론 > 퐁/대명깡 > 치. 론은 응답 전원이 모일 때 한꺼번에 해결한다(더블 론 가능). 론을 패스하면 동순 후리텐, 리치 중이면 영구 후리텐.
- 산 70장 + 왕패 14장. 깡 후 영상패는 `dead[0..3]`에서 뽑고 산 끝에서 1장을 왕패로 보충한다(산이 비면 깡 불가).
- 리치 선언패가 론당하면 공탁(1,000점)이 성립하지 않는다. 성립은 `afterDiscard()`/울림 처리 시점이다.
- 본장·공탁은 첫 화료자(버린 사람 다음 순번)에게만 간다. 점수 합은 항상 `100,000 - 공탁 × 1,000`이다(테스트가 검증).
- 클라이언트로 나가는 뷰(`viewFor`)에는 상대 손패·산·왕패·우라도라가 들어가지 않는다. 결과 화면에서만 공개된 손패가 `result`에 담긴다.

## WebSocket 계약

연결: `/{gameId}/ws?key=<세션키>&name=<닉네임>[&role=p1]`. `key`로 재접속하면 같은 좌석을 이어받는다. 런처 대기실 호스트는 리디렉션 URL의 `role=p1`을 그대로 넘기고, 서버는 방 설정 단계에서 **최초 1회만** 그 연결을 방장으로 인정한다(리디렉션 후 먼저 접속한 사람이 방장이 되는 것을 바로잡음). 이후 `role=p1`은 방장을 바꾸지 못한다.

| 방향 | 메시지 | 역할 |
|---|---|---|
| C→S | `CONFIG {settings}` | 호스트가 대국 길이·적도라·쿠이탕·AI 난이도 변경(방 설정 중) |
| C→S | `START` / `REMATCH` / `LEAVE` | 호스트 시작 / 호스트 다시 하기(방 설정 복귀) / 나가기 |
| C→S | `ACT {action}` | `discard{id,riichi?}` `tsumo` `ankan{kind}` `kakan{id}` `kyuushu` `ron` `pon` `daiminkan` `chi{ids}` `pass` `next` |
| C→S | `ASSIST {on}` | 본인에게만 도우미 힌트 전송 켜기/끄기 |
| S→C | `JOINED` `ROOM` `STATE` `ERROR` | 좌석·방 설정·대국 뷰(`view`, `seats`, `timers`, `hints`, `events`) |

`STATE.view.legal`은 지금 내가 할 수 있는 행동 목록이며 클라이언트는 이것만 신뢰한다. `events`는 효과음·콜아웃용이다.

## 연출(fx)

- `public/js/fx.js`는 비행 패·착지 충격·배너·파티클을 **재렌더로 지워지지 않는 `#fx` 레이어**에 그린다. 클라이언트는 매 STATE마다 `stage.innerHTML`을 갈아엎으므로 연출 DOM을 `#content` 안에 두면 안 된다(렌더 직후 `fx.attach()`).
- 이벤트 연출은 **렌더 후** `playEvents()`에서 한다. 버림 패는 렌더 직전 `captureRects()`로 잡아 둔 손패/상대 패 더미 위치에서 연못의 실제 자리(`.pond [data-id]`)까지 날아가며, 날아가는 동안 실제 패는 `visibility:hidden`(렌더 때마다 `fx.rehide()`)이다.
- 손패 돌리기·뽑기·도라·결과창처럼 재렌더에 끊길 수 있는 연출은 `addAnim`/`S.anims`에 시작 시각을 기억하고 `resumeAnims()`가 경과 시간(`currentTime`)만큼 이어서 재생한다. 새 연출도 이 경로를 쓴다.
- `prefers-reduced-motion`이면 연출은 건너뛰고 효과음만 낸다. 테스트 전용 `?auto=N`은 결과 확인 대기를 `max(2200, N×5)`ms로 둔다(연출 확인용).

## 타이머·자동 진행

- 버림 15초 + 대국 전체 여유 20초, 론/울기 응답 10초, 결과 확인 25초. 초과하면 쯔모기리/패스/다음으로 자동 진행한다.
- 연속 2회 시간 초과하거나 접속이 끊긴 사람은 자동 진행(자리 비움)이 되며 행동하면 해제된다. 리치 후 쯔모·깡 선택지가 없으면 서버가 0.9초 뒤 쯔모기리한다.
- 대국 중 입장은 거절(`in_progress`)된다. 접속자가 0명이 되면 90초 후 방이 초기화된다.

## AI

- 모든 난이도: 효율(향청수 → 수용 장수) 우선 버림, 쯔모·론은 항상 선언한다.
- easy: 방어 없음, 20% 무작위 버림, 울기 확률적. normal: 리치 상대 방어(현물·스지), 역이 보장되는 울기만. hard: 방어 강화, 리치 판단 보수적.
- AI는 `viewFor(seat)`와 `view.legal`만 쓴다. `game.h`(내부 상태)를 직접 읽지 않는다.
- 결정 시간 평균 약 6ms, 최대 80ms 내외. 서버에서 인위적으로 0.7~1.4초(턴)·0.35~0.8초(응답) 지연을 둔다.

## 테스트

```powershell
cd C:\antigravity\minigame-paradise\mahjong
node --test tests/agari.test.js tests/game.test.js tests/server.test.js
npx playwright test --config=playwright.config.js   # UI 회귀(격리 포트에서 서버를 직접 기동)
```

- `tests/helpers.js`의 `playFullMatch(seed)`가 AI 4명으로 한 대국을 끝까지 돌린다. 규칙을 바꾸면 퍼즈(game.test.js 마지막)가 점수 보존과 종료를 확인한다.
- 시나리오 테스트는 `setup()`으로 `game.h`를 직접 구성한다. 같은 종류 패는 4장을 넘기지 않도록 손패를 짠다.
- 고정된 PASS 개수는 문서에 적지 않는다.
- 시연 영상: 런처를 격리 포트(예: 3055)로 띄우고 `node mahjong/tests/record-demo.mjs`(minigame-paradise 루트에서). 가상 플레이어 2명이 입장→준비→대국→첫 국 결과까지 진행하며 영상은 `tests/screenshots/demo-video/`에 남는다.
- 화면 검증용: `MAHJONG_FAST=1 node server.js --port 3042` 후 `/?name=테스터&auto=1`은 자동 진행 모드(테스트 전용)다.

## 변경 시 주의할 점

- 역·부수 판정(`agari.js`)은 같은 패에 대해 모든 분해/대기 해석을 비교해 점수가 가장 높은 것을 고른다. 새 역을 추가하면 `evalStandard`/`addCommonYaku`와 테스트를 함께 갱신한다.
- `legalTurn()`의 `riichiWaits`는 클라이언트의 리치 확인 문구가 사용하므로 형식을 유지한다.
- `view.players[].melds[].called`는 울린 패 id다(암깡은 null). 클라이언트가 눕힌 패 위치를 이 값과 `from`으로 정한다.
- 클라이언트는 매 STATE마다 무대 전체를 다시 그린다. 호버/선택 상태는 `S`(main.js) 안에 두고 DOM에 의존하지 않는다.
- UI 변경은 1200×760 고정 무대가 작은 뷰포트에서 비율 축소되는지 실제 브라우저로 확인한다. 세로 모바일은 가로 모드 안내를 띄운다.

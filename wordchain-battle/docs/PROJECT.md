# 끝말잇기 배틀

> 최종 업데이트: 2026-08-15

끝말잇기 배틀은 하나의 단어 체인을 번갈아 잇는 서버 권위 1:1 전투 게임이다. 단어 길이에 따라 기본 전투 효과가 정해지고, 유효 단어 제출 후 10초 동안 별도 보상을 선택한다.

## 전투 흐름

```text
WORD_INPUT(기본 10초)
  → 서버 단어 검증 및 글자 수 효과 확정
REWARD_SELECT(10초)
  → 보상 선택 또는 시간 초과(보상 없음)
중앙 Combat Resolver
  → Damage/Heal/Buff/Debuff/HP/승패 확정
상대 WORD_INPUT
```

카운트다운에는 시작 글자를 `???`로 숨기고 서버가 정한 선공을 각 플레이어 관점에서 표시한다. 공격 강화 보상은 획득한 현재 공격부터 증가한 Attack으로 계산한다.

클라이언트는 `WORD_SUBMIT { word }`와 `REWARD_SELECT { rewardId }`만 전송한다. 단어 길이, Damage, Heal, 스탯, 시간 효과, State 전환과 승패는 서버가 결정한다. 현재 State와 맞지 않는 요청은 거부한다.

통합 런처에서 사람 대전을 시작하면 로비가 고유 `matchId`와 `p1`/`p2` 역할을 발급하고 게임 서버에 먼저 등록한다. 게임 WebSocket은 이 값이 일치하는 두 연결만 받아 이전 탭의 자동 재접속이 새 경기 슬롯을 차지하지 못하게 한다. 만료된 매치·중복 역할·정원 초과는 재접속 불가 오류로 표시하고 무한 재접속하지 않는다.

## 프로토타입 설정

- 2글자: Damage 4
- 3글자: Damage 8
- 4글자: Damage 12
- 5글자 이상: Damage 16
- 보상: 기존 7종과 조건부 3종 중 서버가 매번 중복 없이 3종을 추첨하며 조건부는 최대 1종만 포함한다. 조건부는 장문 공격(다음 단어 4글자 이상 +8), 속공(서버 WORD_INPUT 시작 후 3초 이내 +8), 정밀타(목표 끝 글자 +10)다.
- 기본 답변시간 10초, 최소 3초, 최대 15초
- 보상 미선택 시 단어 공격은 정상 적용하고 추가 보상만 포기

모든 값과 사용자 표시 문구는 `combat-config.js`에 있다. Damage 공식은 `game.js`의 `calculateDamage()` 한 곳에서만 계산한다.

## UI

게임 화면에는 양측 HP·Attack·Defense·기본 답변시간과 일회성 시간 압박을 항상 표시한다. 글자 수별 Damage 표도 항상 노출한다. 보상 State에서는 무작위 후보 3개를 표시하며 기존 보상은 이름 없이 아이콘과 짧은 효과 문구를, 조건부 보상은 아이콘·짧은 이름·조건·피해량을 사용한다. 클릭 또는 1·2·3 키로 선택한다. 양측의 활성 조건부 보상은 공개 상태 칩으로 표시하고, 정밀타 입력이 목표 글자와 일치하면 입력 안내를 강조한다.

정밀타 종료 결과는 `logs/conditional-rewards/wordchain-conditional-YYYY-MM-DD.jsonl`에 `SUCCESS`, `FAILED_PLAYER_CHOICE`, `FAILED_IMPOSSIBLE`, `FAILED_TIMEOUT`으로 구분해 기록한다. 불가능 판정은 해당 턴의 시작 글자·두음법칙·막힘 대체 글자·이미 사용된 단어를 반영해 실제 제출 가능한 사전 단어 수를 센 분석 전용 값이며 Damage나 플레이어 안내에는 사용하지 않는다.

실제 전장은 좌우의 `MY ARENA`/`RIVAL ARENA`와 중앙 단어 코어로 분리한다. 스탯은 수치와 색상 미터를 함께 사용하고 공격 해결 시 단어 타일 비행·돌진·피격·Damage 팝업을 재생한다. 치명타는 충돌 순간 HP를 0으로 갱신한 뒤 패배 전장 균열·암전·K.O.를 재생하고 결과 모달을 표시한다. 답변 타이머는 타이핑 시선 안에 들어오도록 입력 영역 가장 왼쪽, 제시 글자 앞에 배치하며 매초 숫자 교체 애니메이션과 3초 이하 위험 색상을 사용한다. 입력 영역 아래의 `오늘의 전투 족보`는 항상 노출되며 현재 턴 공격자의 Attack과 대상 Defense를 반영한 예상 Damage와 계산식을 실시간으로 표시한다. 보상 후보는 평소 공간을 차지하지 않고 `REWARD_SELECT`에서만 중앙 모달로 나타난다.

## 사전 누락 후보 운영

서버는 한글 2~30자로 형식이 맞지만 로컬 사전에 없어 `invalid`로 거절된 제출어만 `logs/dictionary-candidates/wordchain-missing-YYYY-MM-DD.jsonl`에 기록한다. 틀린 시작 글자, 중복, 비한글 입력은 사전 후보가 아니므로 기록하지 않는다. 같은 경기에서 같은 플레이어가 같은 단어를 반복 제출해도 한 번만 기록한다. 로그에는 닉네임 등 직접 식별 정보 없이 단어, 요구 시작 글자, 허용 대체 글자, 직전 단어, 사람/AI 모드와 시각만 남긴다.

운영 검토는 다음 명령으로 빈도순 후보를 확인한다.

```bash
npm run review-missing-words -- --min-count 2 --limit 100
```

이미 현재 사전에 들어온 단어는 자동 제외한다. 후보는 실제 명사·고유명사 여부를 확인한 뒤 `data/supplement-words.json`의 적절한 카테고리에 수동 반영하고 `npm run build-words`로 재생성한다. 오타나 비속어가 자동으로 사전에 편입되지 않도록 로그에서 사전으로의 자동 승격은 하지 않는다.

## 유지되는 기존 규칙

- 로컬 한국어 사전 검증과 NFC 정규화
- 공용 체인과 매치 전체 단어 중복 금지
- 두음법칙 및 막힘 종성 대체 시작 글자
- 답변 시간 초과 HP 20 페널티와 자동 체인 진행
- HP 0 패배, 기권, 양쪽 동의 리매치
- 서버 관리형 보통 AI와 연결/봇 인증 격리

## 제거된 시스템

게이지 충전, 답변 속도 기반 충전, 100% 자동 공격, 가비지 음절, 가비지 고정 10 Damage 및 관련 상태·메시지·UI를 사용하지 않는다. 첫 제시 글자는 카운트다운 중 숨기고 게임 시작 시 후속 단어가 충분한 후보에서 무작위로 공개한다.

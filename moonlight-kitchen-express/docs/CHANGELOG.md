# 변경 이력

달빛 주방열차의 사용자 영향이 있는 기능과 에셋 변경을 기록한다.

## 2026-08-15

### 스냅샷 보간과 디스플레이 프레임 렌더링

- 서버 판정 30Hz와 입력 전송 30Hz는 유지하면서, 15Hz 스냅샷 수신 때만 Canvas를 갱신하던 구조를 `requestAnimationFrame` 렌더 루프로 분리했다.
- 최근 스냅샷 수신 간격을 EWMA로 추정하고 한 구간 지연 보간을 적용해 플레이어, 들고 이동하는 아이템, 작업 진행도, 열도와 운행 시간을 디스플레이 주사율에 맞춰 부드럽게 표시한다.
- 소유·공정·설비 상태 전환, 큰 좌표 이동, 페이즈 변경, 재접속과 500ms 이상 패킷 공백은 즉시 최신 권위 위치로 스냅해 과거 경로를 가로질러 그리지 않는다.
- 단위 테스트와 실제 AI 이동 브라우저 테스트에서 15Hz 네트워크 상태를 유지한 채 40fps 이상의 렌더 루프와 스냅샷 사이 중간 좌표 생성을 검증한다.

## 2026-08-14

### AI 동료 1인 플레이

- 로비에 `AI와 혼자 시작`을 추가해 한 명만 연결된 상태에서 빈 슬롯을 `달콩 AI`로 채우고 바로 시작할 수 있게 했다.
- AI는 서버 권위 상태를 직접 수정하지 않고 기존 이동·E·Space 입력 경로만 사용한다.
- 재료 확보부터 손질·조리·플레이팅·정차 배식까지 수행하는 작업 선택과 충돌 설비를 우회하는 격자 경로 탐색을 추가했다.
- 현재 목표·대상·행동·경로 길이·정체 시간을 `aiPlayers` 스냅샷에 노출해 후속 AI 둘 관전 및 녹화 단계에서 분석할 수 있게 했다.
- 사람 입력 없이 P2 AI가 첫 주문을 완주하는 단위 시뮬레이션, 단일 연결의 AI 슬롯 생성 네트워크 테스트, 실제 브라우저 1인 시작 E2E를 추가했다.
- AI별 주문 예약과 공용 중복 방지 상태를 추가하고, 역 마감까지의 예상 완수시간을 기준으로 새 주문을 선택하게 했다.
- 완성 음식을 주문에 지정된 역에서만 배식하고 마감된 음식은 폐기해 오배송과 장기 정체를 막았다.
- 조리 시작 즉시 접시를 선제 확보해 조리기 앞에서 기다리도록 바꿔, 단독 AI 300초 기준 배식량을 2건에서 4건으로 높였다.
- AI 둘 자동 운행에서 서로 다른 주문을 맡아 6건·850점으로 라운드 성공 조건을 달성하는 회귀 테스트를 추가했다.
- 로비에서 서버 AI 둘의 300초 운행을 바로 시작하는 `AI 대 AI 관전`을 추가했다.
- 관전 중 사람 입력을 클라이언트와 서버 양쪽에서 차단하고, Canvas 하단에 각 AI의 현재 행동·담당 주문을 녹화용 HUD로 표시한다.
- 관전 재도전·재접속 유지와 실제 브라우저 두 AI 이동·HUD 캡처를 자동 검증한다.

### 가이드 없는 첫 플레이 UX

- 첫 주문을 즉시 공개하고 첫 메뉴를 달버섯 꼬치로 고정해, 빈 화면에서 무엇을 기다리는지 알 수 없던 구간을 제거했다.
- 권위 스냅샷을 따라 집기·손질·조리·플레이팅·배식을 안내하는 `첫 주문 실전` 코치와 목표 설비 강조를 추가했다.
- 모든 재료·설비에 이름표를 표시하고, 가까운 대상의 실제 키·행동·불가능한 이유를 데스크톱·모바일 공통 HUD로 제공한다.
- 서버가 무시하던 잘못된 상호작용에 `INTERACTION_FEEDBACK`을 보내도록 바꿨다.
- 기능이 없던 플레이팅 작업대 2개를 제거하고 실제 규칙인 `빈 접시 + READY 조리기구` 흐름만 노출했다.
- 텍스트 중심 플레이 가이드의 최초 자동 노출을 없애고 도움말 버튼으로만 열도록 변경했다.
- 두 번째 이후 재료를 손질대에서 꺼낼 때 아이템 검색 중 배열을 반복 변경해 재료가 사라지던 결함을 수정했다.
- 가이드 없이 첫 주문 전체를 완주하는 권위 시뮬레이션 회귀 테스트를 추가했다.

## 2026-07-19

### 4페이지 플레이 가이드

- 최초 구현 당시에는 첫 로비 스냅샷 뒤 한 번 자동 노출했으나, 2026-08-14부터 첫 플레이를 가리지 않도록 도움말 버튼에서만 여는 방식으로 변경했다.
- 로비 전용 버튼과 운행 HUD의 `? 플레이 방법` 버튼으로 언제든 다시 열 수 있게 했다. 연결·결과·종료 확인 오버레이가 보일 때는 가이드가 열리지 않도록 우선순위를 유지했다.
- 1페이지는 주문 확인부터 정차 중 배식까지의 5단계, 2페이지는 달버섯 꼬치·등불잎 만두·혜성무 국수의 실제 설비 조합, 3페이지는 열도 85 이상 P1/P2 동시 냉각, 4페이지는 WASD/방향키·`E`/`Enter`·`Space`·`Q` 조작을 안내한다.
- 제목·본문·버튼·접근성 레이블을 한국어와 영어로 제공하고, 언어를 바꿔도 현재 페이지 의미가 유지되도록 했다.
- 가이드가 열릴 때 눌린 입력을 즉시 중립화하고 이동·상호작용·작업·버리기를 차단했다. 닫힌 뒤에는 새 키 입력부터 정상 처리해 닫기에 사용한 키가 게임 행동으로 이어지지 않게 했다.
- dialog 의미 구조, Tab/Shift+Tab 포커스 트랩, Escape 닫기, 로비 opener·운행 Canvas 초점 복원, `aria-live` 페이지 알림, reduced-motion, 44px 조작 대상을 적용했다.
- 1280×720, 1024×768, 390×844의 한국어·영어 화면에서 dialog 경계, 내부 스크롤, 도움말·런처·연결 상태·HUD 간 교차 면적 0을 검증했다.
- 최종 검증 결과: Node/WebSocket 31/31 PASS, Playwright 15/15 PASS.
- 참고: 스펙 `.Codex/specs/2026-07-19-moonlight-kitchen-guide.md`, 구현 리포트 `.Codex/specs/2026-07-19-moonlight-kitchen-guide-report.md`, QA `.Codex/specs/2026-07-19-moonlight-kitchen-guide-qa.md`.

### GPT Image 에셋 통합

- GPT Image로 생성한 재료, 설비·요리, P1/P2 캐릭터 원본 시트 3장을 `public/assets/gpt-image-sources/`에 추가했다.
- 6재료 4상태 24개, 접시·완성 요리 4개, 설비 13개, 두 캐릭터 4방향 8개로 총 49개 프레임을 구성했다.
- `scripts/build_sprite_atlas.py`와 `npm run atlas:build` 명령을 추가해 원본 시트에서 WebP atlas 3장과 JSON manifest를 재현할 수 있게 했다.
- 모든 프레임을 승인된 15색 팔레트로 정규화하고 128px 셀마다 8% 이상의 투명 안전 여백을 보장했다. 최종 최소 여백은 13px, 팔레트 평균 거리는 0.00, 거리 15 이내 비율은 100%다.
- atlas를 Canvas 렌더러에 연결해 재료 종류와 RAW/PREPPED/COOKED/BURNT 상태, 접시와 완성 요리, 13개 설비, P1/P2 및 이동 방향을 시각적으로 구분할 수 있게 했다.
- `Promise.allSettled` 기반 비차단 preload를 적용했다. atlas 일부가 로드되지 않으면 해당 프레임만 기존 Canvas glyph·도형·벡터로 대체하며, `PREPPING → RAW`, `COOKING → PREPPED` 상태 매핑을 유지한다.
- 모바일에서는 중복 Canvas HUD를 숨겨 주문 카드·타임라인·경고의 겹침을 제거했고, 냉각 패널이 캐릭터와 footer를 가리지 않도록 배치를 조정했다.
- atlas 계약과 품질, 이미지 디코딩, 부분 404 fallback, 실제 게임 렌더, 1280×720·1024×768·390×844 뷰포트, 한국어·영어 UI 회귀 테스트를 추가했다.
- 최종 검증 결과: Node/WebSocket 31/31 PASS, Playwright 6/6 PASS. WebP atlas 합계는 146,266바이트다.

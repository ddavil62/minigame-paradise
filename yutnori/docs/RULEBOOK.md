## §1 게임 개요

- **인원**: 본 구현은 **2인 1:1 PvP** 고정. 표준 룰은 2인 이상 팀전(짝수)이 가능하지만 본 구현은 LAN 1:1 단순화.
- **준비물(전통)**: 윷가락 4개(장작윷 또는 밤윷), 윷판(말판), 말 8개(각 편 4개).
- **목표**: 자기 편 말 4개를 모두 먼저 **완주("났다")** 시키면 승리.

> 출처 — 한국어 위키백과:
> > "윷놀이는 윷가락을 던지고 그 결과에 따라 말(馬)을 이동시켜 승부를 겨루는 전통놀이로, 나무로 윷을 만들어 여러 사람이 윷판 위를 돌아 다니는 표식자(말)로 구성된다. 윷판의 양쪽에 각각 말 4개씩을 놓고 윷을 교대로 던져 결승점을 4개 모두 먼저 통과시키는 편이 이긴다."

- **턴 구조**: 한쪽 편이 윷가락을 던져 결과를 얻고 → 결과대로 말을 옮긴다. 윷·모는 보너스 던지기 발생(§6). 보너스가 모두 소진되면 다음 편으로 차례가 넘어간다.
- **본 구현 채택**: `p1`(빨강) 선공 → `p2`(파랑) 후공. (표준은 양 편이 첫 던지기를 한 번씩 해서 더 큰 결과를 낸 편이 선공이지만, 본 구현은 선후공 결정 단계 생략 — §13-7 참조.)

(구현 위치: `server.js` `resetGame()` — `game.currentTurn = 'p1'`)

## §2 말판(윷판) 구조 + 다이어그램

### §2-1 전통 윷판 (표준)

- 외곽 사각형 둘레에 칸(자리) 20개, 그 안에 두 대각선이 교차하며 중앙(방)에서 만난다.
- 표준 명칭(한국민속대백과/나무위키 기준): 외곽 모서리 4개는 **참먹이(=출발/도착, 좌하)**, **모(좌상)**, **방(중앙)**, **찌(우상)**, **쨀(우하)** 등 다양한 지역 명칭이 있다. 본 구현은 명칭 대신 인덱스(좌표)로만 식별한다.
- 한국어 위키백과 정의:
  > "윷판으로 설명하면 가로 세로 다섯 개의 눈금의 정사각형과 그 안에 교차하는 두 대각선의 모양이며, 출발점은 정사각형의 한 꼭짓점이다."
- 외곽 각 변에는 4개의 일반 칸 + 양 끝 모서리 2개. 한 변에 칸 5개씩 × 4변 - 공유 모서리 4 = **외곽 20칸**.
- 두 대각선 위에 각각 4칸(중간 3 + 중앙 1 공유). 총 칸 수 = 외곽 20 + 대각 좌상~우하 3 + 대각 우상~좌하 3 + 중앙 1 공유 = **29칸**.

### §2-2 본 구현의 인덱스 매핑

본 구현은 표준 29칸을 다음 인덱스로 표현한다 (서버 `server.js` + 클라 `public/js/board.js` 동기).

| 영역 | 인덱스 | 설명 |
|------|--------|------|
| 외곽 좌하 모서리 | `0` | **출발점이자 도착점**. 표준 명칭 "참먹이". |
| 외곽 좌측 변 | `1, 2, 3, 4` | |
| 외곽 좌상 모서리 | `5` | 지름길A 분기점. 표준 명칭 "모(또는 모도)". |
| 외곽 상단 변 | `6, 7, 8, 9` | |
| 외곽 우상 모서리 | `10` | 지름길B 분기점. 표준 명칭 "찌". |
| 외곽 우측 변 | `11, 12, 13, 14` | |
| 외곽 우하 모서리 | `15` | 지름길A 합류 출구. 표준 명칭 "쨀". |
| 외곽 하단 변 | `16, 17, 18, 19` | `19` 다음 외곽 진행 = 완주. |
| 지름길A 중간 | `21, 22` | 좌상(5) → 중앙으로 향하는 두 칸. |
| 지름길B 중간 | `26, 27` | 우상(10) → 중앙으로 향하는 두 칸. |
| 중앙(방) | `23` | 두 대각선이 만나는 칸. 분기점. |
| HOME | `-1` | 보드 외부 (아직 출발 안 한 말). |
| GOAL | `99` | 완주 (보드 외부, 가상 칸). |

⚠️ **인덱스 20, 24, 25, 28은 사용하지 않는다.** 표준 29칸을 단순화로 (20=0과 동일, 24/25/28은 미사용) 처리. (§13-8 참조)

### §2-3 ASCII 다이어그램

진행 방향: 시계 반대 방향(나무위키/위키백과 표준 — "왼쪽으로 도는" 좌선 진행) — 본 구현은 단순화를 위해 0 → 1 → 2 → ... → 19 → 0(완주) 순서로 인덱스를 증가시킨다. 인덱스 증가 방향과 회전 방향(좌선/시계반대)은 별개. board.js의 좌표는 좌하(0) → 좌상(5) → 우상(10) → 우하(15) → 좌하(=0) 순서이다.

```
       (5=좌상 모서리)       (10=우상 모서리)
            ●─── 6 ── 7 ── 8 ── 9 ───●
            │ ╲                       ╱ │
            │   21                 26   │
            │     ╲              ╱      │
            4      22         27        11
            │        ╲       ╱          │
            3          ●(23=중앙·방)    12
            │        ╱       ╲          │
            2      22*       27*       13
            │     ╱             ╲       │
            │   21*               26*   │
            │ ╱                       ╲ │
            ●── 19 ──18 ──17 ──16 ──●
       (0=좌하 모서리 = 출발/도착)    (15=우하 모서리)

  ※ 21*/22*/26*/27*는 같은 인덱스가 시각적으로 대각선 양쪽을 표현하기 위해
     반복 표시된 것이 아니라, 실제로는 21,22,26,27이 각각 한 자리씩 차지하며
     중앙(23)을 향해 한 방향으로만 진행한다. 위 다이어그램은 대각의 시각적
     교차를 강조한 단순화 그림이며, 실제 칸 수는 §2-2 표 기준.
```

진행 시퀀스 요약:
- **외곽 한 바퀴 (지름길 미사용)**: `0 → 1 → 2 → ... → 19 → 완주(GOAL)`. 총 20칸 이동 필요.
- **지름길A (좌상에서 진입)**: `... → 5 → 21 → 22 → 23(중앙) → ?`. 중앙에서 분기(§10).
- **지름길B (우상에서 진입)**: `... → 10 → 26 → 27 → 23(중앙) → ?`. 중앙에서 분기(§10).

(구현 위치: `server.js` `advanceOneCell()`, 클라 `public/js/board.js` `OUTER_COORDS` / `SHORTCUT_A` / `SHORTCUT_B`)

## §3 윷가락 결과 표

### §3-1 윷가락 구성

- 윷가락 4개. 각 가락은 반원통(반달 모양 단면).
- **앞면(평평한 면)** = "배" (배가 위로 보임 = 까졌다). 영어 wiki: *flat side up*.
- **뒷면(둥근 면)** = "등" (등이 위로 보임 = 엎어졌다). 영어 wiki: *round side up*.
- 본 구현은 4개 가락 중 **1개에 빨간 X 마크**를 그려 백도(뒷도) 가락으로 사용한다 (구현: `MARKED_STICK_INDEX = 0`, `public/js/yut.js` `drawStick(..., isMarked=true)`).

### §3-2 결과 표 (표준 + 본 구현)

평평한 면(앞, 배) 개수에 따라 결과가 결정된다. 출처 — Wikipedia Yunnori:
> "The score is determined by counting the sticks that are over, and those that are up. ... One stick over (flat side up) and three sticks up (round side up) is called 'do'. ... All sticks over is called 'yut', whereas all sticks up is called 'mo'."

(주의: Wikipedia 영문판은 *over* = 앞면(flat), *up* = 뒷면(round)으로 용어를 사용한다. 한국어 표준과 시각 방향이 같다.)

| 결과 (한글) | 영문 | 앞면(평평면) 개수 | 이동 칸 수 | 보너스 던지기 | 이론 확률 (각 면 50%) | 실측 분포 (5,000회) |
|---|---|---|---|---|---|---|
| 백도(뒷도/빽도) | backdo | 1 (그 1개가 **마크된 가락**) | **−1** (뒤로) | 없음 | 1/16 ≈ **6.25%** | 6.16% |
| 도 | do | 1 (그 1개가 비마크 가락) | 1 | 없음 | 3/16 ≈ **18.75%** | 18.68% |
| 개 | gae | 2 | 2 | 없음 | 6/16 ≈ **37.5%** | 37.40% |
| 걸 | geol | 3 | 3 | 없음 | 4/16 ≈ **25%** | 24.62% |
| 윷 | yut | 4 | 4 | **있음** | 1/16 ≈ **6.25%** | 6.86% |
| 모 | mo | 0 | 5 | **있음** | 1/16 ≈ **6.25%** | 6.28% |

**핵심 직관**: 평평한 면 개수 = 이동 칸 수 (도=1, 개=2, 걸=3, 윷=4). 모만 예외(0개 → 5칸).
이 매핑이 거꾸로 구현되면 사용자가 즉시 "개가 나왔는데 1칸만 간다"라고 보고한다 (실제 Phase 2 → 2.1 핫픽스 사유, §13-4 참조).

(구현 위치: `server.js` `throwYutSticks()`)

### §3-3 백도(뒷도) 발동 조건

- 4개 가락 중 **마크된 가락(인덱스 0) 1개만** 평평면이 위로 향하고 나머지 3개가 둥근면일 때 발동.
- "도(평평면 1개)"가 발생했을 때, 그 1개가 마크된 가락이면 백도, 마크되지 않은 가락이면 일반 도.
- 전체 확률은 1/16로 고정 (백도 4개 가락 중 1개만 마크되므로 `do` 확률 4/16 중 마크 가락이 평평면인 케이스 1/4 = 1/16).

(구현 위치: `server.js` `throwYutSticks()` `switch case 1`)

### §3-4 표준에 모호한 영역

- **윷가락 종류**: 한국어 위키 — 장작윷(길이 15~20 cm, 지름 3~5 cm), 밤윷(작은 4짝)이 일반적. 5짝 윷도 일부 지역에서 사용된다. 본 구현은 **4짝 고정** (Wikipedia/위키백과의 가장 일반적인 형태).
- **확률**: 한국어 위키 — "실제 물리 윷가락은 평평면이 더 가볍고 넓어 뒷면 확률이 더 높아 불균일 확률 분포를 갖는다." 본 구현은 각 가락 50:50 균등 확률 (§13-3 참조).

## §4 말(馬) — 개수, 출발, 완주

### §4-1 개수

- 각 편 **4개의 말**(전통 명칭 "넉 동"). 본 구현 동일.
- 구현: `server.js` `createPiece()`로 초기화 시 4개 생성 (`p.pieces = [createPiece() × 4]`).

### §4-2 시작 상태 (HOME)

- 모든 말은 게임 시작 시 **HOME 상태**(보드 외부, 인덱스 `-1`).
- HOME 말은 첫 이동 시 보드 칸으로 진입한다.
- 본 구현 UI: P1은 좌하 코너, P2는 우상 코너의 HOME 박스에 표시 (`public/js/piece.js` `isClickOnHomeArea()`).

### §4-3 첫 이동 (HOME → 보드 진입)

- 본 구현: HOME 말에 결과 N을 적용하면 → 칸 `(N − 1)`에 도착. (HOME에서 도 = 칸 0, HOME에서 개 = 칸 1, …)
- 표준에 모호: 일부 지역 룰은 "도(1)를 쓰면 칸 0에 놓는다(=참먹이)" — 본 구현과 동일. 다른 변형은 "도가 나오면 한 칸 더 진행" 등이 있다.

(구현 위치: `server.js` `computeNextCell()` — HOME(-1) → cell 0부터 시작)

### §4-4 완주 ("났다" / "펐다")

- 한국어 위키:
  > "도에서 시작(첫 발)해 한 바퀴를 돌아 참먹이로 돌아오는 것(이것을 '났다' 또는 '펐다'라고 부른다)이 놀이의 목적이다. 단, 중요한 것은 말이 참먹이를 통과해야 나는 것이며 참먹이에서 멈추면 난 것이 아니다."
- 본 구현: 외곽 19 → 다음 외곽 진행 시 GOAL(완주). 모/윷으로 칸 수가 남아도 GOAL 처리(통과 완주).
- **주의**: 표준 룰에서는 "참먹이에서 멈추면 난 것이 아니다"라고 명시되어 있다. 본 구현에서 칸 0에 멈춘 경우와 칸 0을 통과한 경우의 처리는 §13-8 참조.

(구현 위치: `server.js` `advanceOneCell()` outer pathContext — `if (cell === 19) return GOAL`)

## §5 이동 규칙 + 칸 수 표

### §5-1 한 결과 = 한 묶음 이동

- 윷가락을 던져 얻은 한 결과(도/개/걸/윷/모/백도)는 **한 말(또는 한 업힘 묶음)을 한 번** 이동시키는 데 사용한다.
- 결과 큐가 여러 개 쌓인 경우(보너스 던지기 누적, §6), 사용 순서는 자유 — 한국어 위키:
  > "한 번 더 또는 그 이상을 던져 나온 윷들은 모두 순서를 바꾸어 사용할 수 있다."
- 본 구현: 사용자가 결과 칩을 클릭으로 선택 후 말을 클릭하여 이동. (`public/js/ui.js` 결과 큐 칩 클릭 핸들러)

### §5-2 칸 수 표 (외곽 진행 기준)

| 결과 | 이동 칸 수 | 예: 칸 3에서 사용 시 도착 칸 |
|---|---|---|
| 백도 | −1 | 칸 2 |
| 도 | 1 | 칸 4 |
| 개 | 2 | 칸 5 (좌상 모서리 — 다음 이동 시 지름길A 자동 진입, §10) |
| 걸 | 3 | 칸 6 |
| 윷 | 4 | 칸 7 + 보너스 던지기 |
| 모 | 5 | 칸 8 + 보너스 던지기 |

### §5-3 묶음(업힘) 일괄 이동

- 같은 칸에 있는 자기 편 말은 **한 묶음**으로 묶여 다음 이동 시 함께 움직인다.
- 본 구현은 별도 "묶음 객체"를 만들지 않고, 이동 시 `movePiece()` 함수가 시작 칸이 같은 자기 말 인덱스를 모아 `groupIndices`로 일괄 이동시킨다 (`server.js` `movePiece()` 묶음 처리 로직).

### §5-4 표준에 모호한 영역

- **결과 사용 순서**: 위키 — 자유 순서. 본 구현 동일.
- **출발선 처리**: 한 결과로 HOME에서 보드 진입 후, 이어지는 결과로 묶음(업힘)을 한꺼번에 이동시킬 수 있는지는 룰마다 다르다. 본 구현은 묶음 처리가 시작 칸 기준으로 묶이므로 같은 턴 내에 묶음 가능.

## §6 보너스(한 번 더) 던지기

### §6-1 보너스 발생 조건 (표준)

한국어 위키 — 윷을 한 번 더 던지는 기회:
1. **윷**이 나온 경우
2. **모**가 나온 경우
3. **상대 편 말을 잡은 경우** (단, 잡기 결과가 윷·모면 중복 보너스 없음 — 한 번만 다시 던짐)

> 한국어 위키 인용:
> > "윷이나 모를 이용하여 다른 참가자의 행마를 잡은 경우에는 중복해서 다시 던지기를 할 수 없다.(예, 윷이나 모로 잡은 경우, 두 번이 아닌 한 번만 다시 던질 수 있다)"

### §6-2 본 구현

- 윷·모 → `bonus: true` 플래그로 즉시 추가 던지기 허용 (`server.js` `throwYutSticks()` — `bonus: result === 'yut' || result === 'mo'`).
- 잡기 보너스 → `game.capturedBonus = true` 플래그 (`server.js` MOVE_PIECE 핸들러 `if (moveRes.captured) game.capturedBonus = true`).
- 큐가 비어도 `lastResult === 'yut' || 'mo'`이거나 `capturedBonus === true`이면 다시 던질 수 있다 (THROW_YUT 진입 검사).
- 백도는 보너스 없음.

### §6-3 보너스 누적

- 윷·모를 연속 N회 내면 결과가 큐에 N개 누적된다.
- 모든 결과를 사용해야 차례가 넘어간다 (`server.js` MOVE_PIECE 마지막 부분 — `if (pendingResults.length === 0 && !hasBonus) passTurn()`).

### §6-4 표준 vs 구현 차이

⚠️ 한국어 위키 명시: "**윷/모로 잡은 경우 중복 보너스 없음** — 한 번만 다시 던짐."
본 구현에서는 윷·모 보너스 토큰(`lastResult`로 추적)과 잡기 보너스 플래그(`capturedBonus`)가 **별도로** 누적된다. 잡기 결과가 윷·모이면 두 보너스가 모두 발생할 수 있다. → §13-2 참조.

## §7 잡기

### §7-1 표준 룰

- 이동 후 상대 편 말이 있는 칸에 도착하면 **잡기** 발생.
- 잡힌 상대 말(업힘 묶음 포함 **전부**)은 HOME(출발 전 상태)으로 되돌아간다.
- 잡은 편은 보너스 던지기 1회 획득(§6).

> 영문 Wikipedia 인용:
> > "If a mal lands on a station occupied by the opponent's team, the opponent's mal is removed from the course and returned to the starting position, and the current player is allowed to cast again."
> > "If an opponent lands their mal on a station occupied by a group of mals of the opponent, all mals in the group are removed from the course."

### §7-2 본 구현

- `server.js` `resolveLanding()`:
  - 같은 cell에 있는 상대 piece를 순회하며 `op.cell = HOME; op.stack = 1`로 전부 HOME 복귀.
  - `oppCaught > 0`이면 `captured = true` 반환 → MOVE_PIECE 핸들러에서 `game.capturedBonus = true`.
- 업힘 묶음 잡기: 같은 cell의 모든 상대 piece가 일괄 HOME 복귀 (코드: `for (let i = 0; i < opp.pieces.length; i++)`).

### §7-3 표준에 모호한 영역

- 잡힌 말이 HOME으로 복귀할 때 "출발선(칸 0)에 놓이는지 / HOME으로 가는지" 변형이 있다. 본 구현은 **HOME(−1)** 복귀 (보드 외부).
- 한국어 위키:
  > "참먹이에서 멈추면 난 것이 아니다. 상대편 말이 참먹이에서 멈췄다면 참먹이에서 잡을 수 있다."
- 본 구현은 칸 0(참먹이)에서 잡기가 발생하면 동일 처리 (잡힌 말 HOME 복귀 + 보너스).

## §8 업기

### §8-1 표준 룰

- 이동 후 자기 편 말이 있는 칸에 도착하면 **업기** 발생 → 같은 칸의 자기 말이 묶음으로 합쳐져 이후 함께 이동한다.
- 업힌 묶음이 상대에게 잡히면 묶음 전체가 HOME으로 복귀(§7).

### §8-2 본 구현

- 본 구현은 **명시적인 "업힘 객체"를 만들지 않는다.** 대신 `movePiece()` 호출 시 시작 칸이 동일한 자기 piece를 묶음으로 일괄 이동시킨다.
- 시각적으로는 같은 칸의 piece 카운트(stack) 합계를 표시 (`public/js/ui.js` 같은 cell의 piece 개수 표기).
- 코드:
  ```js
  // server.js movePiece()
  if (startCell !== HOME && startCell !== GOAL) {
    for (let i = 0; i < mover.pieces.length; i++) {
      if (i === pieceIdx) continue;
      const mp = mover.pieces[i];
      if (!mp.done && mp.cell === startCell) {
        groupIndices.push(i);
      }
    }
  }
  ```

### §8-3 표준에 모호한 영역

- **업힘 묶음 분리**: 위키 — 업힌 말을 다시 분리하여 따로 이동시키는 변형 룰은 명시되지 않음. 본 구현은 같은 칸의 자기 piece가 무조건 함께 이동 — **분리 불가**.
- **자기 말 칸 통과 시 업힘 발생 여부**: 본 구현은 **도착 칸에 있을 때만** 업힘 발생. 통과 칸은 무영향.

## §9 백도(뒷도/빽도)

### §9-1 표준 룰 (변형 룰)

- 한국어 위키:
  > "윷 중 특정 윷에 표시가 되어있는 윷의 앞부분이 보여 도가 나왔을 경우 말을 한 칸 뒤로 물린다."
- 표준 룰의 **변형(옵션)**. 모든 지역에서 사용하지 않으며 인정 여부는 지역에 따라 다르다.
- 발동 조건: 4개 가락 중 마크된 1개만 평평면이 위로 향함 (= "도"인데 그 1개가 마크 가락).
- 이동: 1칸 뒤로.

### §9-2 본 구현 — 적용 규칙 모음

본 구현은 백도를 **기본 활성화**하며 아래 규칙을 적용한다 (인덱스 0번 가락이 마크 가락).

| 상황 | 처리 |
|---|---|
| 출발한 말(보드 위)에 백도 | 외곽: `cell - 1`로 1칸 뒤로 (`server.js` `computeNextCell()` `steps === -1` 분기) |
| **HOME 말에 백도** | 사용 불가 → 서버가 자동 폐기 (사용자에게 결과는 알려주되 큐에 안 넣음). `THROW_YUT` 핸들러 `canUseBackdo` 체크 |
| 칸 0(출발선)에서 백도 | 그대로 칸 0 유지 (뒤로 못 감) |
| 지름길 안에서 백도 | 진입 모서리로 복귀: `21 → 5`, `22 → 21`, `26 → 10`, `27 → 26` |
| 중앙(23)에서 백도 | `22`로 복귀 (지름길A 경로 가정 — **표준에 명확한 정의 없음**, §13-6 참조) |
| 보너스 턴 | 없음 |

### §9-3 백도 후 출발선 통과 처리 (표준에 모호)

- 한국어 위키:
  > "도를 한 뒤 뒷도가 나와 출발로 오게 된 말이 바로 날 수 있는지도 규칙마다 다르다."
- 본 구현은 칸 0에서 백도 발동 시 칸 0 유지(완주 처리 안 함). 도→백도로 칸 0에 돌아온 말은 한 바퀴 더 돌아야 완주.

(구현 위치: `server.js` `computeNextCell()` `steps === -1` 분기)

## §10 분기점(모서리 + 중앙) 처리

### §10-1 표준 룰 — 모서리 분기

- 한국어 위키:
  > "윷판에서 말이 갈 수 있는 길은 모두 네 가지가 있다. … 모서리에서는 사선으로 이동 선택 가능."
- 좌상(`5`) 또는 우상(`10`) 모서리에 **정확히 멈춘 다음** 이동할 때, **외곽 계속 vs 지름길 진입 중 선택**할 수 있는 것이 표준.
- 모서리를 단순 통과(멈추지 않음)하면 외곽으로 계속 진행 — 지름길 미사용.

### §10-2 본 구현 — 강제 지름길 진입 ⚠️ (§13-1)

- 본 구현은 모서리(5, 10)에 정확히 멈춘 다음 이동 시 **무조건 지름길로 진입**한다.
- 선택지 없음. 클라이언트에 분기 모달 미표시.
- 코드 근거:
  ```js
  // server.js computeNextCell()
  if (cell === 5) {
    pathContext = 'shortcutA';
  } else if (cell === 10) {
    pathContext = 'shortcutB';
  }
  ```
- ⚠️ **사용자가 "이상하다"고 보고한 1순위 후보** — 정통 룰에서는 외곽을 계속 가고 싶어도 가능해야 하는데, 본 구현은 모서리에 멈춘 순간 지름길로 빨려 들어간다. §13-1 참조.

### §10-3 중앙(방) 분기

- 중앙(`23`)에 도달하면 **두 출구 중 선택**:
  - **centerExitA (top)**: 중앙 → 외곽 15(우하) → 16 → 17 → 18 → 19 → GOAL
  - **centerExitB (bottom)**: 중앙 → GOAL **직접 완주** (§13-2)
- 본 구현은 항상 클라이언트 모달로 선택 (`server.js` `awaitingBranch: true` 응답 → 클라이언트 BRANCH_REQUEST 처리 → `CHOOSE_PATH` 응답).

### §10-4 중앙→좌하 출구 단순화 ⚠️ (§13-2)

- 본 구현 centerExitB는 중앙(23)에서 **즉시 GOAL** 처리:
  ```js
  // server.js advanceOneCell() centerExitB
  if (cell === 23) return GOAL;
  ```
- ⚠️ **사용자가 "이상하다"고 보고한 2순위 후보** — 표준 룰에서는 중앙에서 좌하로 가는 경로에 1~2개의 중간 칸이 더 있어, 모/윷 같은 큰 결과 사용 시 출발선을 거쳐 GOAL로 가는 과정이 자연스럽다. 본 구현은 남은 칸 수와 무관하게 즉시 완주 처리. §13-2 참조.

### §10-5 중앙에서 출구 선택 시점 (표준에 모호)

- 표준 룰: 지름길A로 들어온 말은 좌상→중앙→우하 경로가 일반적, 지름길B로 들어온 말은 우상→중앙→좌하 경로가 일반적. 즉 **진입 경로에 따라 출구가 어느 정도 고정**되는 지역이 다수다.
- 본 구현: 진입 경로에 무관하게 양방향 선택 가능 (어느 지름길로 들어왔든 top/bottom 자유 선택). 표준에 모호한 영역이지만 본 구현은 가장 자유로운 정책 채택. §13-6 참조.

## §11 승리 조건

### §11-1 표준 룰

- 자기 편 말 4개 모두 완주("났다") 시 승리.
- 영문 Wikipedia:
  > "The game is won by the team who brings all their mals home first, that is complete the course with all their mals."

### §11-2 본 구현

- `server.js` `resolveLanding()` — `const allDone = mover.pieces.every((p) => p.done);` `finished = allDone`.
- MOVE_PIECE / CHOOSE_PATH 핸들러에서 `if (moveRes.finished)` → `game.winner = player.id; game.started = false; broadcastAll({ type: 'GAME_OVER', winner })`.
- 완주 후 남은 결과 큐가 있어도 즉시 게임 종료.

### §11-3 모/윷 직접 완주

- 본 구현: 완주 칸을 넘어서도 (예: 칸 17에서 모(5) 사용 시) 완주 처리. `advanceOneCell()`의 `if (cell === 19) return GOAL` 분기.
- 표준 룰: "참먹이를 통과해야 난다"는 정의에 따라 동일 — 본 구현 OK.

## §13 구현 노트 (구현 vs 표준 차이)

> 본 섹션은 Planner가 코드 정독 결과 발견한 **구현과 표준의 차이 8건**과, 사용자가 "뭔가 이상하다"고 보고한 의심 후보 3건을 강조한다.
> 영향도: **HIGH** = 즉시 직관 불일치 / **MED** = 특정 시점에 혼란 발생 / **LOW** = 무영향에 가깝거나 의도된 단순화

### §13-1 ⚠️ 모서리 분기: 강제 지름길 vs 선택 [HIGH] **— 사용자 의심 후보 1순위**

| 영역 | 모서리 분기 (§10-2) |
|---|---|
| **표준 룰 (출처: 한국어 위키)** | "모서리에서는 사선으로 이동 선택 가능" — 모서리에 정확히 멈추면 다음 이동 시 외곽 계속 vs 지름길 진입 **선택**. |
| **현재 구현** | `server.js` `computeNextCell()` — `cell === 5`이면 `pathContext = 'shortcutA'`, `cell === 10`이면 `'shortcutB'`로 **고정**. 선택지 모달 미표시. |
| **영향도** | **HIGH** |
| **사용자 영향** | 플레이어가 모서리에 도착했을 때 외곽으로 계속 가고 싶어도 강제 지름길로 빨려 들어감. 즉각적인 "이상하다" 직관의 **주요 원인 후보**. |
| **해결 방향** | **수정 권장**: 모서리 도착 시 BRANCH_REQUEST를 발송하여 클라가 "외곽 / 지름길" 모달을 표시하게 하고, 응답에 따라 `pathContext`를 결정한다. 기존 중앙(23) 분기 처리 패턴을 그대로 재사용 가능. CLAUDE.md에 "단순화 결정"으로 명시되어 있으므로 정책 변경이 필요하다면 Purposer 단계에서 결정. |

| 영역 | 중앙 분기 좌하 출구 (§10-4) |
|---|---|
| **표준 룰** | 중앙(방)에서 좌하 방향으로 진행할 경우 외곽 합류 후 출발선(참먹이)을 통과해야 완주. 중앙과 좌하 사이에 1~2개의 칸(전통 명칭 "쨀밭", "날밭" 등)을 더 거치는 것이 일반적. |

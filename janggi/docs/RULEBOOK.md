## §1 게임 개요

- **격자판**: 가로 9줄(file) × 세로 10줄(rank), 총 9×10 = 90 교차점
- **좌표계**: `file ∈ [0..8]`(가로), `rank ∈ [0..9]`(세로). `(0,0)`은 **한(漢) 진영 좌측 상단**
- **진영**:
  - **한(漢)** — 적색(red), `rank 0..4` 영역
  - **초(楚)** — 청색(blue/green), `rank 5..9` 영역
- **기물 수**: 각 진영 16개씩(궁 1, 사 2, 차 2, 포 2, 마 2, 상 2, 졸/병 5) = 총 32개
- **선후수**: **한(漢)이 선수**(먼저 둠), 초(楚)가 후수
- **승리 조건**: 적 궁(王)을 외통수로 만들기 / 적 기권 / 시간패 유발 / 점수제 종료에서 점수 우위
- **목표**: 적 왕(궁)을 잡거나, 합법 수를 모두 봉쇄하여 외통수를 만든다.

> **표준 호환 메모**
> KJA 2009 룰에서 한이 선수이며 초는 후수에 대한 보상으로 **덤 1.5점**을 받는다. 본 구현은 좌표계에서 한 진영이 `rank` 작은 쪽(상단), 초 진영이 `rank` 큰 쪽(하단)을 차지한다.

## §2 판 구조

### §2-1 좌표계

```
       file →    0   1   2   3   4   5   6   7   8
              ┌────────────────────────────────────┐
       rank 0 │ R   ?   ?   A   K   A   ?   ?   R  │ ← 한 진영 1행
       rank 1 │ ·   ·   ·   ·   ·   ·   ·   ·   · │
       rank 2 │ ·   C   ·   ·   ·   ·   ·   C   · │
       rank 3 │ P   ·   P   ·   P   ·   P   ·   P │
       rank 4 │ ·   ·   ·   ·   ·   ·   ·   ·   · │   ← 강(江)
       rank 5 │ ·   ·   ·   ·   ·   ·   ·   ·   · │   ← 강(江)
       rank 6 │ P   ·   P   ·   P   ·   P   ·   P │
       rank 7 │ ·   C   ·   ·   ·   ·   ·   C   · │
       rank 8 │ ·   ·   ·   ·   ·   ·   ·   ·   · │
       rank 9 │ R   ?   ?   A   K   A   ?   ?   R  │ ← 초 진영 10행
              └────────────────────────────────────┘

  ? = 마/상 (배치 코드별 §4 참조)
  R=차, A=사, K=궁, C=포, P=졸/병
```

(참고: lib/board.js `createInitialBoard()` 기준)

### §2-2 궁성(宮城)

- **한 궁성**: `file 3..5, rank 0..2` (3×3 격자)
- **초 궁성**: `file 3..5, rank 7..9` (3×3 격자)
- **궁성 대각선이 그려진 칸 (5칸)**: 꼭짓점 4개 + 중앙 1개
  - **한 궁성**: `(3,0), (5,0), (4,1), (3,2), (5,2)`
  - **초 궁성**: `(3,7), (5,7), (4,8), (3,9), (5,9)`
- 궁성 변 중앙 4칸 `(4,0)(3,1)(5,1)(4,2)`은 **대각선이 그려져 있지 않다** (한 궁성 기준 — 초 궁성도 동일 패턴).

```
한 궁성:                  초 궁성:
  (3,0)─(4,0)─(5,0)        (3,7)─(4,7)─(5,7)
    │ ╲   │   ╱ │            │ ╲   │   ╱ │
  (3,1)─(4,1)─(5,1)        (3,8)─(4,8)─(5,8)
    │ ╱   │   ╲ │            │ ╱   │   ╲ │
  (3,2)─(4,2)─(5,2)        (3,9)─(4,9)─(5,9)
```

- 대각선 인접 관계는 **꼭짓점 ↔ 중앙**만 직접 연결된다. 꼭짓점끼리는 중앙을 경유해야 한다.
- (구현: `lib/board.js` `isPalaceDiagonal()`, `lib/pieces.js` `PALACE_DIAG_ADJ`)

### §2-3 강(江, 경계)

- `rank 4`와 `rank 5` 사이가 **강**이다. 한 진영은 `rank 0..4`, 초 진영은 `rank 5..9`.
- 졸/병은 강을 건너면 **돌아올 수 없다**. 본 구현에서는 졸/병 후방 이동이 항상 불가하므로(§5-7) **동일 효과**로 처리된다.

## §3 기물 점수 (KJA 2009)

| 기물 | 한자 | 코드 | 점수 |
|---|---|---|---|
| 차(車) | chariot | R | **13** |
| 포(包) | cannon | C | **7** |
| 마(馬) | horse | H | **5** |
| 상(象) | elephant | E | **3** |
| 사(士) | advisor | A | **3** |
| 졸/병(兵) | soldier | P | **2** |
| 궁(王) | king | K | **0** (잡히면 즉패) |

- **덤(DEOM)**: 후수 초(楚)에게 **+1.5점** 보정(선수 한의 선착 이점 보상). 점수제 종료 시 합산.
- 초기 보드 한 진영 총점(덤 미포함) = `13×2 + 7×2 + 5×2 + 3×2 + 3×2 + 2×5 = 72점`. 초도 동일하나 덤 적용 시 73.5점.
- (구현: `lib/score.js` `PIECE_SCORE`, `DEOM`, `calculateScore()`)

## §4 마/상 배치 4종 + 선후수

### §4-1 배치 코드

마/상만 배치 가능한 자리(`file 1, 2, 6, 7`, 각 진영의 마지막 rank)에 4글자 코드를 적용한다. 코드는 `file 1, 2, 6, 7` 순서.

| 코드 | file 1 | file 2 | file 6 | file 7 | 통칭 |
|---|---|---|---|---|---|
| **MSMS** | 마 | 상 | 마 | 상 | 원앙마 (안마장) |
| **SMSM** | 상 | 마 | 상 | 마 | 양귀마 |
| **MSSM** | 마 | 상 | 상 | 마 | 귀마 |
| **SMMS** | 상 | 마 | 마 | 상 | 면상 |

(구현: `lib/board.js` `SETUP_MAP`)

### §4-2 배치 순서 (응수 권리)

1. **초(楚)가 먼저 배치**를 선언한다.
2. 한(漢)이 초의 배치를 확인하고 **자신의 배치를 응수**로 선언한다.
3. 두 배치가 확정되면 게임이 시작되고, **한이 첫 수를 둔다**.

> **표준에 명시**: 초가 후수의 핸디캡 보상으로 배치 우선권을 갖고, 한은 응수 권리(반응 선택권)를 갖는다. (KJA 2009)

- 배치 선택 제한 시간: **30초**(미선택 시 기본 `MSMS`). 본 구현은 `applySetupChoice()`가 제한 시간을 enforce하지는 않으나(서버 로직에서 별도 타이머), 표준 정책으로 기재.
- (구현: `lib/game.js` `applySetupChoice()`, `VALID_SETUPS = ['MSMS','SMSM','MSSM','SMMS']`)

### §4-3 가능한 조합

`4(초) × 4(한) = 16가지` 모두 합법.

## §5 기물별 이동 규칙

### §5-1 궁(王) — King

- **이동 범위**: 자기 궁성 내 직선 1칸 + (자기 칸이 대각선 칸이면) 대각선 1칸
- **대각 이동 조건**: 출발 칸이 §2-2의 "그려진 대각선 칸"(꼭짓점 또는 중앙)일 때만 가능
- **꼭짓점 ↔ 중앙**만 직접 연결(꼭짓점 ↔ 꼭짓점은 직접 불가, 중앙 경유)

```
한 궁성 대각 이동 예시 (궁 (4,1) 중앙):
  → 직선 4방향: (3,1)(5,1)(4,0)(4,2)
  → 대각 4방향: (3,0)(5,0)(3,2)(5,2)
  총 8개 후보 (장애물·자살수 미고려)

한 궁성 꼭짓점에서 (궁 (3,0)):
  → 직선 2방향: (4,0)(3,1)  // (3,-1) 보드 밖
  → 대각 1방향: (4,1)        // 중앙으로만
  총 3개 후보
```

- (구현: `lib/pieces.js` `getKingMoves()`)

### §5-2 사(士) — Advisor

- **궁과 동일 규칙**. 궁성 내 직선 1칸 + 그려진 대각선 1칸.
- 본 구현은 `getAdvisorMoves()`가 `getKingMoves()`를 그대로 호출한다.

### §5-3 차(車) — Chariot

- **직선 이동**: 상하좌우 4방향, 임의 거리. 경로상 기물이 있으면 정지. 적 기물이면 잡고 정지, 아군이면 직전에서 정지.
- **궁성 대각선 이동**: 차가 궁성 내 대각선 칸에 있을 때 대각 방향으로 이동 가능.
  - **중앙에 있을 때**: 4 꼭짓점 모두 1칸 이동 가능 (아군 점유 시 불가)
  - **꼭짓점에 있을 때**:
    - 중앙이 비어있으면 → 중앙 + **반대편 꼭짓점**(2칸 관통)까지 이동 가능
    - 중앙에 적 기물이 있으면 → 중앙(잡기)까지만 가능, 반대편 꼭짓점 불가
    - 중앙에 아군이 있으면 → 이 방향 대각 이동 전체 불가

```
차 (3,0)에서 (5,2) 관통 예시:
  (3,0)차 → 대각선 ↘ → 중앙(4,1) 비어있음 → (5,2) 도착 가능
  중앙(4,1)에 적 기물이면 → (4,1)만 잡기 가능, (5,2) 도착 불가
```

> **표준에 모호 — 본 구현 정책 §13-2 참조**
> KJA 표준은 차의 궁성 대각 이동 범위를 "대각선을 따라 임의 거리"로 기술하나, 본 구현은 PALACE_DIAG_ADJ 맵 기반으로 **꼭짓점 ↔ 중앙 ↔ 반대편 꼭짓점**(최대 2칸 관통)까지만 허용한다. 꼭짓점에서 비인접 꼭짓점으로의 직접 이동(예: (3,0)→(5,2)는 중앙 경유로만 가능, (3,0)→(3,2)는 직선 이동에서 처리)은 동일한 결과를 낸다.

- (구현: `lib/pieces.js` `getChariotMoves()`, `addChariotPalaceDiagonal()`)

### §5-4 포(包) — Cannon

- **직선 이동**: 4방향 임의 거리. 다음 두 조건을 모두 만족해야 한다.
  - **다리(bridge)** 정확히 1개를 넘어야 한다. 다리 없이 이동 불가.
  - 다리 너머 첫 기물(빈 칸 포함) 자리로 이동 가능.
- **제약 1**: **다리가 포(아군·적 불문)면 넘을 수 없다.**
- **제약 2**: **적 포는 잡을 수 없다.** (다리 너머 칸의 기물이 포면 이동/포획 불가)
- **궁성 대각선 이동**: 꼭짓점에서 중앙을 다리로 삼아 반대편 꼭짓점으로 이동.
  - 중앙이 비어있으면 불가 (다리 없음)
  - 중앙이 포면 불가 (포가 다리 안 됨)
  - 도착(반대편 꼭짓점) 칸에 적 포가 있으면 불가
  - **중앙 출발 포는 대각 이동 불가** (다리 구조상 다리가 존재하지 않음)

```
포 직선 이동 예시:
  (0,5)포, (3,5)에 비-포 기물, (6,5)에 적 기물(비-포), (8,5)공백
  → (0,5)→(4,5)(5,5)(6,5) 가능: 다리=(3,5), 대상=(6,5) 잡기
  → (7,5)(8,5) 불가: 다리 너머에 이미 적 기물(잡기 후 정지)

포 궁성 대각 예시 (초 궁성):
  포(3,7), 중앙(4,8)에 비-포 기물(아군 사 등), (5,9)공백
  → (5,9) 이동 가능
  중앙(4,8)이 포(아군이든 적이든) → 이동 불가
```

- (구현: `lib/pieces.js` `getCannonMoves()`, `addCannonPalaceDiagonal()`)

### §5-5 마(馬) — Horse

- **이동 패턴**: 직선 1칸 + (그 방향에 수직인) 대각 1칸 = L자형. 총 8방향.
- 최종 변위: `(±1, ±2)` 또는 `(±2, ±1)`.
- **멱 규칙(1회)**: **직선 1칸 경유 칸**(중간 칸)에 기물이 있으면(아군·적 불문) 그 방향 2칸 모두 불가.

```
마 (4,5)에서 8방향 후보:
  위(4,4) 경유 → (3,3)(5,3)
  아래(4,6) 경유 → (3,7)(5,7)
  좌(3,5) 경유 → (3,4)(3,6)
  우(5,5) 경유 → (5,4)(5,6)

  (4,4)에 기물 있으면 → (3,3)(5,3) 불가 (멱)
```

- (구현: `lib/pieces.js` `getHorseMoves()`)

### §5-6 상(象) — Elephant

- **이동 패턴**: 직선 1칸 + (그 방향에 수직인) 대각 1칸 + (같은 대각 방향으로) 한 번 더 1칸. 총 8방향.
- 최종 변위: `(±2, ±3)` 또는 `(±3, ±2)`.
- **멱 규칙(2회)**:
  - **첫 번째 멱**: 직선 1칸 경유 칸에 기물 → 그 방향 모든 대각 불가
  - **두 번째 멱**: 대각 1칸 경유 칸에 기물 → 해당 도착 칸 불가
- 마보다 이동 범위 크고 멱 포인트 2개로 더 까다롭다.

```
상 (4,5)에서 위 방향 예시:
  직선 1칸: (4,4) - 첫 번째 경유, 비어있어야 함
  대각 1칸: (3,4) 또는 (5,4) - 두 번째 경유, 비어있어야 함
  도착: (2,3) 또는 (6,3) - 변위 (±2, ±3)
```

- (구현: `lib/pieces.js` `getElephantMoves()`)

### §5-7 졸(兵) — Soldier

- **한 졸**: 앞(`rank+1`) 1칸 + 좌(`file-1`) 1칸 + 우(`file+1`) 1칸. 총 3방향. **후방(`rank-1`) 불가**.
- **초 병**: 앞(`rank-1`) 1칸 + 좌 1칸 + 우 1칸. 후방(`rank+1`) 불가.
- **궁성 대각 이동(보너스)**: 적 궁성의 그려진 대각선 위에 있으면 앞 대각 1칸 이동 가능.
  - 조건: `inPalace(file, rank, enemySide)` AND `isPalaceDiagonal(file, rank)` AND 목적 칸도 `isPalaceDiagonal()`.
  - 본 구현은 출발 칸과 도착 칸 **모두** 대각선 칸이어야 한다(§13-1 참조 — 결과 동일).

```
한 졸 (3,7) - 초 궁성 꼭짓점 위:
  앞(3,8) - palace diag? false → 일반 직진만
  앞 대각(4,8) - palace diag? true → 이동 가능
  결과: (4,8) 대각 앞 이동 + (4,7) 우 1칸 + (2,7) 좌 1칸 + (3,8) 앞 1칸
```

- (구현: `lib/pieces.js` `getSoldierMoves()`)

## §6 한 수의 순서 (턴 구조)

1. **현재 차례 진영**이 자기 기물 1개를 이동한다 (**패스 불가**).
2. 이동 후 **턴 전환**: 다음 차례는 상대 진영.
3. 수를 두면 **무승부 제안 자동 취소** (제안 상태 초기화, §8-7).
4. **초읽기 중**에 수를 두면 해당 측의 초읽기 타이머가 **30초로 리셋**된다 (`mainSec <= 0 && byoyomiLeft > 0`일 때만).
5. 적 궁(王)을 잡는 수 → **즉시 게임 종료**(승리).
6. 이동 후 자기 궁이 장군 상태가 되는 수(자살수)는 **거부**된다 (§8-3).

- (구현: `lib/game.js` `applyMove()`)

## §7 승패 판정 (KJA 2009)

### §7-1 외통수 (Checkmate)

- 장군 상태에서 합법 수가 하나도 없으면 **외통수** → 해당 진영 패배.
- 본 구현은 `applyMove()` 내부에서 적이 외통수에 빠지면 즉시 종료, 또는 적 궁을 잡으면 즉시 종료 처리.
- **궁 포획 = 외통수와 동등**: 본 구현은 궁이 잡힌 경우(`captured.type === 'king'`)도 `endReason: 'checkmate'`로 종료한다.
- (구현: `lib/rules.js` `isCheckmate()`, `lib/game.js` `applyMove()` 궁 포획 분기)

### §7-2 점수제 종료

- **점수제로 종료되는 경우**: 동형반복 3회 / 50수 룰 / 무승부 합의.
- 점수 계산: `calculateScore(board)` → 양 진영 남은 기물 합산 + 초에 덤 1.5 가산.
- **승자 판정**:
  - `scores.han > scores.cho` → **한 승**
  - 그 외(동점 포함) → **초 승** (덤 1.5 효과로 정수 점수에서 사실상 동점 불가)
- (구현: `lib/score.js` `getScoreWinner()`)

### §7-3 기권

- 어느 진영이든 자발적으로 기권 가능 → **상대 승리**.
- 종료 후에는 기권 불가.
- (구현: `lib/game.js` `applyResign()`)

### §7-4 동형반복 3회

- `boardHash(board, turn)` — **보드 상태 + 다음 차례**를 결합한 해시 — 가 3회 등장 시 점수제 종료(룰북 §7-2 적용).
- `repetitionHistory: Map<hash, count>`에 매수 이후 등록. **count 3 = isThreefold = true**.
- 초기 배치 완료 직후 첫 해시도 1회 카운트(시작 상태 포함).
- (구현: `lib/rules.js` `countRepetition()`, `lib/board.js` `boardHash()`, `lib/game.js` `startGame()`/`applyMove()`)

### §7-5 시간패

- 본 시간 + 초읽기 모두 소진 시 시간패 → 상대 승. 자세한 시간 규칙은 §9 참조.

## §8 특수 규칙

### §8-1 멱 (Blocking)

- 마/상의 **직선 1칸 경유 칸**에 아군 또는 적군 기물이 있으면 해당 방향 이동 전체 차단.
- 상은 추가로 **대각 1칸 경유 칸**도 비어있어야 한다 (멱 2회).
- 멱은 **진영 불문** (아군 점유도 멱이 된다).

### §8-2 포다리 (Cannon Bridge)

- 포는 다리(중간 기물) 없이 이동 불가.
- **포는 포를 다리로 삼을 수 없다.** (다리가 포면 그 방향 이동 전체 불가)
- **포로 포를 잡을 수 없다.** (대상이 포면 그 자리 진입/포획 불가)

### §8-3 자살수 금지

- 자기 기물을 이동시킨 결과 **자기 궁이 장군 상태가 되는 수**는 불법.
- 서버에서 `wouldBeSelfCheck()`로 시뮬레이션하여 거부. 클라이언트에는 `error: '자살수는 둘 수 없다 (궁이 장군 상태가 된다)'`로 응답.
- 장군 상태에서 장군을 해소하지 않는 수도 자살수 필터에 의해 자동 차단된다.
- (구현: `lib/rules.js` `wouldBeSelfCheck()`, `lib/game.js` `applyMove()` step 5)

### §8-4 장군 (Check)

- 적 기물의 **합법 이동 범위에 자기 궁이 포함되는 상태**.
- 장군 발생 시 서버는 `CHECK` WS 메시지를 브로드캐스트 (`result.check = true`).
- 장군을 당한 측은 다음 수에서 반드시 장군을 해소해야 한다 (해소 못 하면 외통수 또는 자살수).
- (구현: `lib/rules.js` `isInCheck()`)

### §8-5 양수겸장 (Double Check)

- 2개 이상의 기물이 동시에 장군을 부르는 상태. `isDoubleCheck() = true`.
- **양수겸장 시 응수**: 규칙상 두 공격 기물을 동시에 막을 수 없으므로 **궁 이동만이 가능한 응수**가 된다.
- 본 구현은 별도의 "양수겸장 강제" 로직이 없으나, `getAllLegalMoves()`의 자살수 필터(§8-3)가 장군 해소 불가 수를 모두 제거하므로 **결과적으로 궁 이동만 남는다**. (§13-7 구현 노트 참조)
- (구현: `lib/rules.js` `isDoubleCheck()`)

### §8-6 빅장 (Perpetual Check)

- KJA 2009: 빅장(연속 장군)은 **무승부도 패배도 아닌 합법 수**이다. 일반 합법 수로 처리.
- 본 구현은 빅장 카운터/패널티가 없으며, 연속 장군도 정상 처리. 동형반복 3회에 걸리면 §7-4에 따라 점수제 종료된다.
- (구현: 별도 분기 없음 — §13-6 참조)

### §8-7 무승부 제안

- 어느 측이든 자기 차례에 무승부 제안 가능 (`applyDrawOffer('offer')`).
- 상대는 수락/거절 선택. 수락 시 점수제 종료(`endReason: 'draw_score'`), 거절 시 제안 취소.
- 제안 후 상대가 수를 두면(또는 자기가 수를 두면) **자동 취소**.
- (구현: `lib/game.js` `applyDrawOffer()`, `applyMove()`의 `state.drawOfferedBy = null`)

## §9 시간 제한

- **본 시간**: 각 진영 **600초** (10분)
- **초읽기**: **30초 × 3회**
- **본 시간 차감**: 자기 차례 1초마다 `mainSec -= 1`
- **초읽기 전환**: `mainSec = 0`이 되면 다음 tick부터 `byoyomiSec`이 차감되기 시작
- **초읽기 회차 소진**:
  - `byoyomiSec <= 0` 되면 `byoyomiLeft -= 1`, `byoyomiSec` 다시 30으로 리셋, 다음 회차 시작
  - `byoyomiLeft <= 0`까지 도달하면 **시간패** → 상대 승 (`endReason: 'timeout'`)
- **수를 둔 후 초읽기 리셋**:
  - 본 시간이 남아있을 때(mainSec > 0): 리셋 불필요
  - 본 시간 소진 후 초읽기 중(mainSec = 0 && byoyomiLeft > 0): `byoyomiSec`을 30으로 리셋
- (구현: `lib/game.js` `TIME_CONFIG`, `tickTimer()`, `resetByoyomiForTurn()`)

```
TIME_CONFIG = { mainTimeSec: 600, byoyomiSec: 30, byoyomiCount: 3 }
```

## §10 종료 조건 요약

| 사유 | endReason | 판정 함수 / 위치 |
|---|---|---|
| 외통수 (장군+합법 수 0) | `checkmate` | `isCheckmate()` 또는 궁 포획(`captured.type === 'king'`) |
| 기권 | `resign` | `applyResign()` |
| 시간패 | `timeout` | `tickTimer()` |
| 동형반복 3회 | `repetition` | `countRepetition().isThreefold` → 점수제 |
| 50수 룰 | `fifty_move` | `noCaptureOrSoldierMoves >= 50` → 점수제 |
| 무승부 합의 | `draw_score` | `applyDrawOffer('accept')` → 점수제 |

- 점수제 종료 시(`repetition`, `fifty_move`, `draw_score`) `state.endScores`에 `{han, cho}`(덤 1.5 포함) 저장.
- (구현: `lib/game.js` `endGame()`)

## §11 금지 수

다음 수는 서버에서 거부되거나 합법 후보에 포함되지 않는다.

1. **자살수** (§8-3): 자기 궁이 장군 상태가 되는 모든 이동
2. **포가 포를 다리로 삼는 이동** (§5-4 제약 1, §8-2)
3. **포로 포를 잡는 이동** (§5-4 제약 2, §8-2)
4. **궁/사 궁성 밖 이동** (§5-1, §5-2)
5. **졸/병 후방 이동** (§5-7)
6. **마/상 멱이 발생하는 이동** (§5-5, §5-6, §8-1)
7. **차/포 직선 경로상 장애물 통과** (§5-3, §5-4)
8. **아군 기물 잡기** (모든 기물)
9. **장군 상태에서 장군을 해소하지 않는 수** (자살수 필터에 의해 자동 차단, §8-3 + §8-4)
10. **유효하지 않은 배치 코드** (`VALID_SETUPS = ['MSMS','SMSM','MSSM','SMMS']` 외, §4)
11. **상대 차례에 둔 수**, **상대 기물 이동**, **자기 차례 외 무승부 수락** 등 절차 위반

## §12 QA 체크리스트

본 체크리스트는 룰북의 모든 핵심 룰을 자동 테스트로 커버하기 위한 기준이다. `tests/rulebook-c*.spec.js`에서 본 항목들을 검증한다.

- [ ] 초기 배치: 4종 코드 × 32개 기물 위치 정확 (§4-1, §2)
- [ ] 선수: **한**(漢), 배치 순서: **초 → 한** (§4-2)
- [ ] **궁/사**: 궁성 밖 이동 불가 (§5-1, §5-2)
- [ ] **궁**: 꼭짓점 ↔ 꼭짓점 직접 이동 불가 (중앙 경유만) (§5-1)
- [ ] **차**: 직선 장애물 통과 불가, 아군 점유 칸 진입 불가 (§5-3)
- [ ] **차**: 궁성 대각선 이동 정확 (꼭짓점 ↔ 중앙 ↔ 반대편 꼭짓점) (§5-3, §13-2)
- [ ] **포**: 다리 없이 이동 불가 (§5-4, §8-2)
- [ ] **포**: 포-포 다리 금지 / 포로 포 잡기 금지 (§8-2)
- [ ] **포**: 궁성 중앙 출발 대각 이동 불가 (§5-4, §13-3)
- [ ] **마**: 멱 차단 정확 (직선 1칸 경유) (§5-5, §8-1)
- [ ] **상**: 멱 차단 정확 (직선 1칸 + 대각 1칸 경유, 멱 2회) (§5-6, §8-1)
- [ ] **졸/병**: 후방 이동 불가 (§5-7)
- [ ] **졸/병**: 적 궁성 대각선 위에서만 대각 앞 이동 가능 (§5-7)
- [ ] **장군**: `isInCheck()` 정확 (적 합법 이동 범위에 자기 궁) (§8-4)
- [ ] **외통수**: 장군 + 합법 수 0개 → `isCheckmate() = true` (§7-1)
- [ ] **궁 포획**: 즉시 `gameOver = true`, `endReason = 'checkmate'` (§7-1)
- [ ] **자살수 거부**: 서버가 `error: '자살수…'`로 응답 (§8-3)
- [ ] **양수겸장**: `isDoubleCheck()` 정확 (2개 이상 기물 동시 장군) (§8-5)
- [ ] **양수겸장 응수**: `getAllLegalMoves()`가 궁 이동만 반환 (§8-5, §13-7)
- [ ] **빅장**: 연속 장군 합법 수로 허용 (패배 아님) (§8-6, §13-6)
- [ ] **동형반복 3회**: `endReason = 'repetition'`, `endScores` 설정 (§7-4)
- [ ] **50수 룰**: 비포획·비졸 이동 50회 누적 → `endReason = 'fifty_move'` (§7-2, §10)
- [ ] **50수 카운터 리셋**: 포획 또는 졸/병 이동 시 → 0 (§7-2)
- [ ] **덤 1.5**: 초 점수에 자동 포함 (`calculateScore(board, true)`) (§3)
- [ ] **점수제 승자**: `han > cho`만 한 승, 그 외 초 승 (§7-2)
- [ ] **기권**: 상대 승, `endReason = 'resign'` (§7-3)
- [ ] **무승부 제안 → 수락**: 점수제 종료 (`endReason = 'draw_score'`) (§8-7)
- [ ] **무승부 제안 → 거절**: `drawOfferedBy = null`, 게임 계속 (§8-7)
- [ ] **무승부 제안 후 수**: `drawOfferedBy = null` 자동 취소 (§8-7)
- [ ] **시간 tick**: 본 시간 → 초읽기 → 시간패 흐름 정확 (§9)
- [ ] **초읽기 리셋**: 수를 두면 `byoyomiSec`이 30으로 리셋 (단, 본 시간 소진 후에만) (§9)

## §13 구현 노트 (룰 vs 구현 불일치)

본 섹션은 코드 정독 결과 식별된 **표준 룰과 구현 사이의 차이 또는 특이사항**을 기록한다.
각 항목은 다음 형식을 따른다.

> **영역명** / **표준 룰**(출처) / **현재 구현**(파일·함수) / **영향도**(HIGH/MED/LOW) / **해결 방향**

### §13-1 졸 궁성 대각 이동 — 출발/도착 칸 모두 대각선 요구

- **영역**: §5-7 졸/병 궁성 대각 이동
- **표준 룰**: 졸/병이 적 궁성의 그려진 대각선 위에 있을 때 대각 앞 이동 가능 (KJA 2009, 나무위키)
- **현재 구현** (`lib/pieces.js::getSoldierMoves`):
  ```js
  if (inPalace(file, rank, enemySide) && isPalaceDiagonal(file, rank)) {
    // 좌앞/우앞 대각: 도착 칸도 isPalaceDiagonal()이어야 함
    if (inPalace(lfF, lfR, enemySide) && isPalaceDiagonal(lfF, lfR)) { ... }
  }
  ```
  도착 칸도 `isPalaceDiagonal()`을 만족해야 함.
- **영향도**: **LOW**
- **해결 방향**: **무영향** — 궁성 대각선은 꼭짓점 ↔ 중앙만 연결되므로 출발이 대각선 칸이면 대각 앞 1칸 도착지도 자연스럽게 대각선 칸이다. 구현과 표준의 결과가 동일.

### §13-2 차 궁성 대각 — 꼭짓점 → 꼭짓점 직접 이동 범위 제한

- **영역**: §5-3 차 궁성 대각선 이동
- **표준 룰**: 차는 궁성 대각선 위에서 대각 방향으로 **임의 거리** 이동 가능 (KJA 2009)
- **현재 구현** (`lib/pieces.js::addChariotPalaceDiagonal`):
  - 꼭짓점에서 중앙 비어있을 때 → 중앙 + **반대편 꼭짓점**(2칸 관통)까지만 허용
  - 인접하지 않은 꼭짓점 간 직접 이동(예: (3,0) → (5,2))은 중앙(4,1) 경유로 처리되므로 동작상 동일
  - 단, **대각선 임의 거리**라는 표현은 실제로 궁성 내부에서 최대 2칸(꼭짓점-중앙-꼭짓점)이 한계이므로 구현 제한이 표준 결과와 동등하다.
- **영향도**: **LOW**
- **해결 방향**: **룰북에 정책 명기** (본 문서 §5-3에 표기 완료). 코드 수정 불필요.

### §13-3 포 궁성 중앙 출발 대각 이동 불가

- **영역**: §5-4 포 궁성 대각 이동
- **표준 룰**: 포는 다리가 있어야 이동 가능 (KJA 2009)
- **현재 구현** (`lib/pieces.js::addCannonPalaceDiagonal`):
  ```js
  if (file === centerF && rank === centerR) {
    // 중앙에 있는 포: 대각선으로 이동 불가 (다리가 없음)
    return;
  }
  ```
- **영향도**: **LOW**
- **해결 방향**: **무영향** — 중앙이 출발점이면 대각 방향에 다리(중간 기물)가 존재할 수 없으므로 표준과 일치.

### §13-4 50수 룰 트리거 조건

- **영역**: §7-2 점수제 종료 (50수)
- **표준 룰**: "기물을 잡거나 졸/병이 이동하면 카운터 초기화" (KJA 2009)
- **현재 구현** (`lib/game.js::applyMove`):
  ```js
  const isSoldierMove = piece.type === 'soldier';
  if (captured || isSoldierMove) {
    state.noCaptureOrSoldierMoves = 0;
  } else {
    state.noCaptureOrSoldierMoves++;
  }
  ```
- **영향도**: **무영향**
- **해결 방향**: **일치** — 별도 조치 불요.

### §13-5 동형반복 초기 해시 등록

- **영역**: §7-4 동형반복
- **표준 룰**: 동일 보드 상태가 3회 반복되면 동형반복으로 점수제 종료
- **현재 구현** (`lib/game.js::startGame`):
  ```js
  // 초기 보드 해시를 반복 기록에 등록
  const hash = boardHash(state.board, state.turn);
  countRepetition(state.repetitionHistory, hash);
  ```
  초기 상태도 1회 카운트하므로 초기 상태로 2회 더 돌아오면 트리거.
- **영향도**: **무영향**
- **해결 방향**: **일치** — 표준 정의 그대로.

### §13-6 빅장(연속 장군) 처리

- **영역**: §8-6 빅장
- **표준 룰**: 빅장은 무승부도 패배도 아닌 합법 수 (KJA 2009)
- **현재 구현**: 빅장 전용 카운터/패널티 없음. 연속 장군도 일반 합법 수로 처리.
- **영향도**: **무영향**
- **해결 방향**: **일치** — 단, 동형반복 3회에 자연스럽게 걸려 점수제 종료될 수 있음(룰에 부합).

### §13-7 양수겸장 강제 응수 로직 부재

- **영역**: §8-5 양수겸장
- **표준 룰**: 양수겸장 시 궁 이동만이 가능한 응수
- **현재 구현** (`lib/rules.js`):
  - `isDoubleCheck()`는 판정만 수행
  - `applyMove()`에 "양수겸장이면 궁 이동만 허용" 같은 명시적 제한 코드 **없음**
  - 그러나 `getAllLegalMoves()`의 자살수 필터(`wouldBeSelfCheck()`)가 장군 해소 불가 수를 모두 제거하므로 **결과적으로 궁 이동만 합법으로 남는다**
- **영향도**: **LOW**
- **해결 방향**: **룰북에 정책 명기** (본 문서 §8-5 및 본 §13-7에 기록 완료). 코드 수정 불필요. 자살수 필터로 동일 효과 달성.

### §13-8 무승부 제안 후 수에 의한 자동 취소 방향

- **영역**: §8-7 무승부 제안
- **표준 룰**: 무승부 제안은 상대 응답 전까지 유효. 일반적으로 "한 수가 두어지면 제안 무효"
- **현재 구현** (`lib/game.js::applyMove`):
  ```js
  // 무승부 제안 초기화 (수를 두면 제안 취소)
  state.drawOfferedBy = null;
  ```
  제안자/상대자 누구든 수를 두면 즉시 `drawOfferedBy = null`로 초기화.
- **영향도**: **LOW**
- **해결 방향**: **무영향** — KJA 표준은 "상대가 응답 전에 수를 두면 자동 거절"로 해석되며, 본 구현은 "자기가 수를 두어도 자동 취소"로 더 보수적. 결과적으로 부정 사용(제안 후 자기가 수 두면 유효 유지)을 방지하므로 안전한 정책.

## 부록 B: 외부 출처 인용

본 룰북 작성 시 다음 외부 자료를 교차 검증에 사용했다.

1. **대한장기연맹(KJA) 2009 개정 룰** — 본 룰북의 1차 출처. 점수표, 덤 1.5, 50수 룰, 빅장 처리, 시간 제한(10분 + 30s × 3) 등 핵심 룰의 권위 표준.
2. **나무위키 「장기」** (https://namu.wiki/w/장기) — 마/상 배치 4종 명칭(원앙마/양귀마/귀마/면상), 궁성 대각선 구조, 졸 궁성 보너스 이동에 대한 교차 검증.
3. **Wikipedia 「Janggi」** (https://en.wikipedia.org/wiki/Janggi) — 영문 자료로 차/포 궁성 대각 이동 규칙, 외통수 판정 표준 교차 검증.
4. **한국기원 장기부 표준 안내** — 외통수/장군/자살수 용어 정의 교차 검증.

> **참고**: 위 출처들은 일부 세부 룰(예: 차의 궁성 대각 임의 거리 vs. 본 구현의 최대 2칸 제한)에서 미세한 해석 차이가 있을 수 있다. 본 룰북은 모호한 경우 §13에서 본 구현의 정책을 명시하는 방식으로 처리한다.

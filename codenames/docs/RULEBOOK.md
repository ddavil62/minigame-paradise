## §1 게임 개요

- **장르**: **2팀 경쟁** 워드게임. 레드 팀과 블루 팀이 자기 팀의 비밀 요원(카드)을 먼저 모두 찾아내면 승리한다.
- **인원(표준)**: 2~8인 (팀당 최소 2명). **본 구현은 2:2 고정** — 각 팀이 [스파이마스터 1 + 요원 1]로 구성된 **4인 휴먼 전용**. (LAN 미니게임천국 통합 패키지 정책 + 휴먼 전용)
- **핵심 반전**: **역할별 시야 분리.** 스파이마스터는 25칸의 정답(키 카드)을 모두 알지만, 요원은 공개된 카드만 본다. 스파이마스터의 한 단어 단서로 요원이 정답 카드를 추론한다.
- **목표**: 자기 팀 색의 카드를 전부(선공 9장 / 후공 8장) 먼저 공개한다. 단, **암살자 카드를 건드리면 즉시 패배**한다.

> 출처 — English Wikipedia:
> > "Codenames is a 2015 word-based party game ... two teams compete to see who can make contact with all of their agents first."

## §2 구성물 — 단어 보드 + 키 카드

### §2-1 단어 보드 (25칸)

- 단어팩에서 무작위로 뽑은 **25개 단어**를 5×5 격자에 배치한다. 인덱스 = 보드 위치(0~24).
- 본 구현은 한국어 단어팩(`codenames-duet/words.js`에서 복사한 독립 `words.js`)을 사용한다.

### §2-2 키 카드 (단일 공유 키, 25칸)

스파이마스터들만 보는 정답표. 25칸 각각이 아래 4종 중 하나의 색을 갖는다:

| 색 | 한글 | 장수 | 의미 |
|----|------|------|------|
| 선공팀(red 또는 blue) | 선공팀 요원 | **9** | 선공팀이 찾아야 할 카드 |
| 후공팀(blue 또는 red) | 후공팀 요원 | **8** | 후공팀이 찾아야 할 카드 |
| neutral | 중립(행인) | **7** | 누가 골라도 턴만 종료 |
| assassin | 암살자 | **1** | 고른 팀 즉시 패배 |

- 합계 = 9 + 8 + 7 + 1 = **25**.
- **클래식의 핵심 차이(vs 듀엣)**: 듀엣은 플레이어별 시점 키 2장(`{left, right}` 쌍)이지만, 클래식은 **모든 스파이마스터가 공유하는 단일 색상 배열**이다.

> 본 구현: `game.js buildKeyCard(firstTeam)` — 선공팀 9 / 후공팀 8 / 중립 7 / 암살자 1을 채운 뒤 Fisher-Yates 셔플. `createGame()`이 합계 불변식을 검증한다.

## §3 역할 배정 — 스파이마스터 / 요원

각 팀은 두 역할로 나뉜다:

| 역할 | 시야 | 행동 |
|------|------|------|
| **스파이마스터(spymaster)** | 키 카드 **전체** 색상을 본다 | 자기 팀 턴에 단서(단어 + 숫자) 1개를 제출(§5) |
| **요원(operative)** | **공개된** 카드 색만 본다 (미공개는 회색) | 단서를 보고 카드를 클릭(추측)하거나 패스(§6) |

- **본 구현 배정 절차(role_select 대기실)**: 4인이 게임 서버(`/codenames/`)에 입장하면 `phase='role_select'`에서 팀(레드/블루) + 역할(스파이마스터/요원)을 자유 선택한다.
  - 같은 (팀, 역할) 자리는 1명만 점유 가능(서버 중복 가드).
  - 4개 슬롯(레드 마스터·레드 요원·블루 마스터·블루 요원)이 모두 채워지면 **호스트**(첫 입장자)의 START 버튼이 활성화된다.
- 표준 보드게임은 팀 합의로 스파이마스터를 정하지만, 본 구현은 대기실에서 명시적으로 선택한다 — §13-3.

## §4 키 카드 + 선공 결정

- **선공팀 = 9장을 가진 팀.** 어느 색(레드/블루)이 9장인지는 **매 게임 랜덤**으로 결정된다.
- 보드 상단에 팀별 잔여 카드 수("레드 N – 블루 M")와 선공팀을 표시한다.
- 선공팀이 먼저 단서를 주며, 첫 단계는 `turnPhase='clue'`(선공팀 스파이마스터 단서 대기)로 시작한다.

> 본 구현: `createGame(startTeam?)` — `startTeam` 미지정 시 `Math.random() < 0.5`로 선공팀 랜덤. 리매치는 직전 선공팀의 반대를 인자로 넘겨 교체한다(§11).

## §5 게임 진행 — 스파이마스터 단서 규칙

자기 팀 턴이 되면 스파이마스터가 **단서 1개**를 제출한다. 단서는 **한 단어 + 숫자**로 구성된다.

- **단어**: 이번 단서로 연결하려는 카드들을 암시하는 한 단어.
- **숫자**: 그 단어와 연관된 자기 팀 카드의 개수.
- 단서 제출 후 단계가 `clue` → `guess`로 전환되고, 요원이 추측을 시작한다.

### §5-1 단서 검증 (본 구현)

- **표준 룰**: 단서 단어는 보드에 보이는 단어이면 안 되고, 합성어·발음 힌트 등 다양한 하우스룰 제약이 있다.
- **본 구현(LAN 신뢰 환경)**: 공백·길이 **최소 검증만** 수행한다(빈 단어 거부, 30자 절단, 숫자 1~9 정수 검증). 보드 단어 포함 여부 등 강한 자연어 검증은 **Out of Scope** — §13-4.
- 자기 팀 턴·`clue` 단계가 아니면 거부(ERROR). 이미 단서가 활성화돼 있으면 거부.

> 본 구현: `game.js giveClue(state, team, word, number)` — `guessesLeft = number + 1`(§6 보너스), `turnPhase='guess'`로 전환.

## §6 추측 규칙 + 한도(숫자+1)

요원은 단서를 보고 카드를 클릭해 공개한다.

- **추측 한도 = 단서 숫자 + 1** (정통 보너스). 예: 단서 "동물 3"이면 최대 4번 추측 가능.
- 한도 내에서 자기 팀 카드를 맞히면 계속 추측할 수 있다(§7).
- 요원은 언제든 **패스(END_TURN)**로 조기 종료할 수 있다(단, 단서가 나온 뒤에만).

> 본 구현: `giveClue`가 설정한 `guessesLeft`를 `guessCard`가 자기 팀 적중마다 감소. `endTurnByPass(state, team)`가 명시적 패스를 처리.

## §7 카드 클릭 결과별 처리

요원이 클릭한 카드의 키 색에 따라 처리가 갈린다:

| 키 색 | 결과 | 처리 |
|-------|------|------|
| 자기 팀 색 | `correct` | 해당 팀 found +1. 자기 팀 전체 공개면 **즉시 승리**(§10). 아니면 `guessesLeft -= 1`, 0이면 턴 종료, 남으면 **턴 유지**(계속 추측). |
| 중립(neutral) | `neutral` | **즉시 턴 종료**(§8). |
| 상대 팀 색 | `opponent` | 상대 팀 found +1 → 상대가 이 카드로 전체 공개를 완성하면 **상대 즉시 승리**. 아니면 **즉시 턴 종료**. |
| 암살자(assassin) | `assassin` | 클릭한 팀 **즉시 패배**, 상대 승리(§9). |

- 이미 공개된 카드 재클릭, 잘못된 인덱스, 추측 한도 0, 자기 팀 턴 아님, `guess` 단계 아님은 모두 ERROR.

> 본 구현: `game.js guessCard(state, team, cardIndex)` — 위 4분기를 순수 함수로 처리하고 `{result, turnEnded, win}`을 반환.

## §8 턴 종료 조건

현재 팀의 턴은 다음 중 하나로 종료된다:

1. **추측 한도 소진** (`guessesLeft === 0`).
2. **중립 카드** 적중.
3. **상대 팀 카드** 적중(상대 진척 +1 후).
4. **요원 패스**(END_TURN).

턴 종료 시 상대 팀의 `clue` 단계로 전환되고 `currentClue=null`, `guessesLeft=0`으로 초기화된다.

> 본 구현: `game.js endTurn(state, team)` — `currentTeam`을 상대로 교체, `turnPhase='clue'` 초기화. 암살자/승리로 게임이 끝난 경우는 턴 교대 없이 종료.

---

## §9 암살자 패배

- 키 카드에 **암살자는 단 1장**이다.
- 어느 팀이든 암살자 카드를 클릭하면 **그 팀이 즉시 패배하고 상대가 승리**한다. 게임이 즉시 종료(`gamePhase='over'`, `winReason='assassin'`)된다.
- 암살자는 게임에서 가장 위험한 변수이며, 스파이마스터 단서 설계의 핵심 제약이다.

---

## §10 승리 조건

- **카드 전체 공개**: 자기 팀 색 카드(선공 9 / 후공 8)를 전부 공개하면 그 팀 **즉시 승리**(`winReason='completed'`).
  - 자기 팀 차례에 직접 완성할 수도 있고, 상대가 실수로 우리 팀 카드를 클릭해 마지막 한 장을 채워 줘 승리할 수도 있다(§7 `opponent` 분기).
- **암살자 패배에 의한 승리**: 상대가 암살자를 클릭하면 우리 팀이 승리한다(§9).

> 본 구현: `game.js checkTeamWin(state, team)` — `found >= total`이면 승리 확정. 게임 종료 시 서버가 키 카드 전체를 복기(review) 데이터로 공개한다(`GAME_OVER.review`).

## §11 리매치

- 게임 종료 후 "한 판 더"에 양 팀에서 **각각 1명 이상** 동의하면 재시작한다(omok REMATCH 패턴 참조).
- 재시작 시 **선공팀을 교체**(직전 선공의 반대 팀이 9장)하고 보드(단어 + 키 카드)를 재생성한다. **역할 배정은 유지**된다.
- 시퀀스: `REMATCH`(C→S) → 한쪽만 동의면 `REMATCH_WAITING { readyIds }`, 양 팀 동의면 `REMATCH_START { firstTeam }`.

> 본 구현: `server.js tryRematch(requester)` — `rematchPending: Set`에 동의 누적, 레드·블루 양쪽 동의 시 `createGame(nextFirst)`로 선공 교체 재생성.

## §12 구현 제약 + QA 체크리스트

### §12-1 구현 제약

- **휴먼 전용 4인(2:2).** AI 봇은 미구현 — `botAvailable: false`. 단, 슬롯 구조(`Player.ws` 자리 + `createApp` `getBotUrl` 훅)는 봇 삽입이 가능하도록 예약돼 있다(§13-2).
- **LAN 신뢰 환경.** 단서 자연어 검증은 최소(§5-1). 강한 안티치트는 Out of Scope.
- **codenames-duet과 완전 독립.** 교차 import 금지(words.js 포함). 런처는 URL 첫 세그먼트(`codenames` vs `codenames-duet`)로 정확히 분리한다.
- **단독 실행 포트 3014**(충돌 시 +1 폴백). 통합 런처에서는 단일 포트(3000) 라우팅.

### §12-2 QA 체크리스트

룰북 기반 테스트는 아래 항목을 §번호 인용으로 커버한다.

#### 단서·추측(§5, §6, §7)

## §13 구현 노트 (구현 vs 표준 차이)
